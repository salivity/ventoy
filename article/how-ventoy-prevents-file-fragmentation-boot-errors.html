How Ventoy Prevents File Fragmentation Boot Errors

This article explains the technical mechanisms Ventoy uses to reliably boot ISO and image files regardless of physical drive fragmentation. Unlike traditional boot utilities that fail when an image is broken into non-contiguous clusters across a storage device, Ventoy combines native filesystem drivers, dynamic in-memory block mapping, runtime BIOS/UEFI firmware hooks, and OS-stage virtual drive emulation to ensure seamless execution.

The Problem with Traditional ISO Booting

Standard multi-boot tools and BIOS-based bootloaders often rely on disk-chaining mechanisms that assume an ISO file occupies a single, continuous sequence of sectors on a storage drive. When files are written, deleted, and rewritten on a USB drive, the filesystem naturally fragments larger files. If a traditional loader attempts to map an ISO by its starting sector and total length, any fragmented clusters point to unrelated data, corrupting the payload and crashing the boot sequence.

1. Embedded Filesystem Drivers

Ventoy operates on a custom-patched GRUB2 core that incorporates native read drivers for modern filesystems, including exFAT, NTFS, ext3/ext4, UDF, and XFS. Instead of reading raw sector offsets provided by a host OS during installation, Ventoy navigates the target partition's file allocation structures (such as the File Allocation Table in exFAT or the Master File Table in NTFS) directly at boot time. This allows it to identify the exact location of every fragmented cluster associated with an ISO file.

2. Dynamic Extent Mapping (Scatter-Gather Tables)

Once an image is selected from the boot menu, Ventoy reads the file’s cluster chain and builds a runtime memory table containing every fragmented segment (known as extents). Each entry in this scatter-gather list records:

  • The starting Logical Block Addressing (LBA) sector on the physical USB drive.
  • The length of that continuous segment.
  • The corresponding virtual LBA sector inside the emulated ISO.

This dynamic mapping translates a fragmented physical file into an unbroken, contiguous virtual address space purely in memory.

3. Firmware-Level Interception (BIOS and UEFI)

Before handing control to the kernel inside the ISO, Ventoy establishes hooks at the firmware level to ensure read requests are translated according to the scatter-gather table:

  • Legacy BIOS (INT 13h Hooking): Ventoy installs a memory-resident handler for BIOS interrupt INT 13h. When the guest bootloader attempts to read sectors from the emulated CD/DVD drive, the hook intercepts the request, queries the fragment table, and directs the hardware to read the exact corresponding physical sectors on the USB drive.
  • UEFI (EFI_BLOCK_IO_PROTOCOL): In modern UEFI systems, Ventoy registers a virtual device handle that implements the EFI_BLOCK_IO_PROTOCOL (and EFI_BLOCK_IO2_PROTOCOL). When the target operating system's EFI bootloader requests blocks, Ventoy’s custom driver intercepts the call, splits or redirects the read requests across the fragmented segments, and returns the data as if it came from an unfragmented optical disc.

4. Preserving the Mapping into the OS Kernel

The most difficult challenge in booting fragmented files occurs when the operating system kernel initializes, loads its own USB drivers, and drops BIOS/UEFI runtime services. At this stage, traditional firmware hooks are discarded.

Ventoy solves this transition using secondary hooks tailored to specific operating systems:

  • Linux: Ventoy injects an initramfs hook or daemon that locates the physical ISO using filesystem labels and constructs a loopback device or Device Mapper (dm-linear) table. This ensures the Linux kernel continues to see a single unified block device.
  • Windows: Ventoy utilizes a companion virtual disk driver (ventoy.sys) or pre-boot memory patches that create an emulated CD-ROM drive directly within Windows Setup, redirecting physical I/O requests through the host driver without relying on physical drive continuity.

Through this multi-stage interception model, Ventoy eliminates the technical requirement for defragmentation, allowing users to copy, move, or modify ISO files freely without risking boot failure.
