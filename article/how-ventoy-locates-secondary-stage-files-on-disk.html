How Ventoy Locates Secondary Stage Files on Disk

This article provides an overview of how the Ventoy bootloader transitions from its initial boot stage to its secondary stage files on disk. Ventoy achieves this through a distinct dual-partition layout, embedded filesystem drivers, and device-handle matching using partition labels and UUIDs to locate and load its secondary GRUB runtime environment seamlessly across both legacy BIOS and UEFI platforms.

The Dual-Partition Architecture

When Ventoy is installed on a drive, it splits the storage medium into two distinct partitions:

  • Partition 1 (Data): Typically formatted as exFAT, NTFS, FAT32, or ext4, this partition occupies most of the disk and holds user ISO files, images, and standard data.
  • Partition 2 (VTOYEFI): A small, dedicated hidden partition (usually around 32MB) formatted as FAT. This partition houses the core boot environment, including UEFI executables, legacy stage loaders, core GRUB2 modules, and secondary stage configurations.

BIOS vs. UEFI Initial Entry Points

The mechanism used to locate the secondary stage depends on the system's firmware:

  1. Legacy BIOS: The Master Boot Record (MBR) contains the initial bootstrap code. During installation, Ventoy writes a specialized stage 1 loader into the MBR and the reserved sectors immediately following it. This initial code contains embedded sector offsets or block lists pointing directly to the early core image (core.img) stored within the boundaries of Partition 2.
  2. UEFI Systems: The UEFI firmware natively mounts Partition 2 as an EFI System Partition (ESP). The firmware loads \EFI\BOOT\BOOTX64.EFI (or architecture-appropriate binaries such as BOOTIA32.EFI or BOOTAA64.EFI) directly from the FAT filesystem.

Locating Partition 2 at Runtime

Once the initial stage (GRUB core image or EFI binary) executes, it must dynamically locate its secondary stage files (GRUB configuration files, modules, and themes) rather than relying on static disk numbers, which can change depending on how the host motherboard enumerates drives.

To locate the secondary stage files, Ventoy performs the following steps:

  1. Boot Drive Identification: Ventoy queries the firmware (using BIOS INT 13h drive numbers or UEFI LoadedImage and BlockIO protocol handles) to verify the exact physical disk from which the system booted. This prevents the bootloader from accidentally reading a secondary partition from a different Ventoy drive attached to the machine.
  2. Filesystem and Partition Scanning: Ventoy's early core includes a minimal, compiled-in FAT filesystem driver. With this driver, the core image can parse the partition table (MBR or GPT) on the boot drive.
  3. Signature and UUID Matching: The secondary files are identified by searching for the filesystem label VTOYEFI or by matching the specific partition UUID written during the initial Ventoy formatting process.

Loading the Secondary Stage Environment

Once the VTOYEFI partition is identified, the initial stage sets GRUB's root and prefix variables to point directly to the secondary stage directory (such as /ventoy or /EFI/BOOT on Partition 2). The core loader can then read the FAT filesystem natively, load additional runtime modules (such as drivers for exFAT, NTFS, and ISO9660), execute configuration scripts, and launch the user interface that lists bootable image files.
