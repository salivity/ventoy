Boot GParted Live with Persistence on Ventoy

Running GParted Live with persistence on a Ventoy multiboot USB drive is technically possible, but it does not work completely seamlessly out of the box. Because GParted Live is built on Debian Live, it can leverage Debian's native persistence mechanism, which Ventoy supports through its persistence plugin. However, because GParted Live is designed to run entirely from RAM to prevent drive locking, achieving persistence requires manually creating a persistence image file, configuring a JSON file, and modifying boot parameters at startup.

The Short Answer

Ventoy can boot GParted Live with persistence, but not in a single, automated step. While standard desktop distributions like Ubuntu or Debian Live integrate with Ventoy's persistence plugin with minimal setup, GParted Live’s bootloader configuration does not include the necessary persistence cheat codes by default.

Why It Is Not Fully Seamless

  1. Missing Kernel Parameters: Debian Live requires the persistence boot parameter to detect and mount an overlay storage device. GParted Live’s standard boot menu options omit this flag to force the system to load into volatile memory.
  2. Drive Locking Conflicts: Persistence requires writing session changes to a partition or an image file on the USB drive. If the persistence file resides on the same drive that Ventoy is running from, that drive becomes locked, preventing GParted from safely modifying, resizing, or formatting the Ventoy USB drive itself.

How to Configure GParted Live Persistence on Ventoy

To set up persistence for GParted Live through Ventoy, you must configure Ventoy's persistence plugin manually:

  1. Create the Persistence Image: Use Ventoy's CreatePersistentImg.sh script (on Linux) or a similar image-generation tool to create an .img or .dat file formatted with an ext4 filesystem. The filesystem label must be named persistence.
  2. Add a persistence.conf File: Mount the newly created image file and create a file inside its root directory named persistence.conf. Add the line / union inside this file to tell the system to store all filesystem modifications. Unmount the image file.
  3. Configure ventoy.json: Place the image file in your Ventoy drive (for example, inside a ventoy or ISO folder). Open or create the ventoy/ventoy.json configuration file and map your GParted ISO to the persistence file: 
    {
    "persistence": [
        {
            "image": "/gparted-live.iso",
            "backend": "/gparted-persistence.dat"
        }
    ]
}
  4. Append the Boot Parameter: Boot into Ventoy, select the GParted Live ISO, and choose the persistence option if prompted. When the GParted boot menu appears, press e (or Tab, depending on UEFI or Legacy BIOS mode) to edit the boot parameters. Add the word persistence to the end of the linux boot line, then boot the system.

Is Persistence Necessary for GParted?

For most workflows, running GParted Live with persistence is unnecessary. GParted is a specialized utility intended strictly for partitioning and disk management rather than daily computing. Custom scripts, extra drivers, or network settings can generally be scripted or executed via the terminal without needing to preserve the root environment across reboots.
