Does Ventoy Alter ISO Files When Booting?

Ventoy does not alter a single byte of an ISO file during either the copying process or the boot process. When you place an image onto a Ventoy USB drive, the file remains completely untouched, maintaining identical cryptographic checksums (such as MD5 or SHA-256) before and after booting. Ventoy achieves this by using in-memory virtualization rather than modifying the underlying file or extracting its contents.

The Copying Process

When you copy an ISO file to a Ventoy drive, your operating system performs a standard file transfer to a standard filesystem (typically exFAT, NTFS, or ext4). Ventoy does not intercept, unpack, recompile, or inject data into the file during this write operation. The file stored on the disk partition is an exact, bit-for-bit duplicate of the source file you downloaded.

The Boot Process

Traditional multiboot tools often extract the contents of an ISO or alter configuration files to make them bootable from USB media. Ventoy operates differently:

  1. Hardware Emulation in RAM: Upon selecting an ISO from the Ventoy menu, the bootloader hooks standard BIOS interrupts (such as INT 13h) or UEFI Block I/O protocols entirely in system memory.
  2. Virtual Drive Mapping: Ventoy maps the virtual optical disc directly to the raw, contiguous storage sectors occupied by the ISO on the flash drive.
  3. Read-Only Access: The operating system being booted accesses the ISO through these memory hooks, treating the file as a physical, read-only CD or DVD.

Because all mapping and runtime redirection occur strictly in volatile RAM, the physical disk sectors housing the ISO are never written to.

Handling Dynamic Writes and Persistence

Many modern live operating systems require write access during runtime to handle temporary logs, system states, or user data. Even in these cases, the original ISO remains untouched:

  • RAM Disks (OverlayFS): Most live Linux environments create a temporary filesystem in RAM for any write operations, discarding changes upon reboot.
  • Ventoy Persistence Plugins: If you configure Ventoy for persistence, all changes are routed to a separate dedicated image file (such as a .dat file) defined in the configuration. The primary ISO remains strictly read-only.

How to Verify

You can verify that Ventoy preserves data integrity by generating a SHA-256 hash of your original ISO file on your host machine. Copy the file to the Ventoy drive, boot from it, shut down the computer, and recompute the SHA-256 hash directly from the USB drive. The checksum will match the original hash identically, confirming that zero bytes were modified.
