Why Linux Splash Screens Flicker After Ventoy Menu

When booting a Linux distribution from a Ventoy USB drive, the brief flickering or black screen that occurs between the Ventoy menu and the OS splash screen is primarily caused by graphics hardware handoffs. This visual disruption stems from the transition between the generic firmware framebuffer used by the bootloader and the native Kernel Mode Setting (KMS) drivers loaded by the Linux kernel, a process often compounded by Plymouth’s display initialization in live environments.

The Graphics Handshake: GOP to Kernel Mode Setting (KMS)

Ventoy relies on GRUB2 to display its interface. Under modern UEFI systems, GRUB renders using the UEFI Graphics Output Protocol (GOP), while legacy BIOS systems rely on standard VESA modes. These protocols use a basic, unaccelerated software framebuffer to display graphics at a set resolution.

Once you select an operating system, control passes to the Linux kernel. Early in the boot process, the kernel unloads the firmware's generic display driver and initializes native hardware drivers (such as amdgpu, i915, or nouveau/nvidia). This process is known as Kernel Mode Setting (KMS). When KMS initializes, the graphics card's display controller is physically reset to configure native resolutions, color depths, and refresh rates. This hardware reset momentarily cuts the video signal, resulting in a visible flash or a black screen.

Plymouth Initialization and Double-Buffering

The animated splash screen seen during Linux startup is typically managed by Plymouth. Plymouth is designed to create a seamless transition from bootloader to desktop, but it requires access to the display buffer.

If Plymouth launches before the native GPU drivers are fully loaded, it temporarily attaches to the basic UEFI framebuffer. Once the kernel finishes loading the native KMS driver, Plymouth must drop the temporary buffer and rebind to the new Direct Rendering Manager (DRM) interface. This secondary handoff causes a second flicker or causes the splash animation to stutter, disappear, and reappear.

Live ISO Limitations vs. Installed Systems

Installed Linux systems can be tuned to eliminate flicker using techniques like "seamless boot" or "fastboot" (e.g., preserving the GOP framebuffer smoothly into KMS via early initramfs driver loading).

Ventoy, however, boots standard live ISO images. These images are engineered for broad hardware compatibility rather than visual optimization. Live environments typically:

  • Do not load native GPU drivers in the earliest stages of the initial ramdisk (initramfs).
  • Lack hardware-specific kernel parameters (such as i915.fastboot=1) that prevent unnecessary mode switches.
  • Force a safe, baseline resolution that must be changed later in the boot sequence to match the monitor's native panel timing.

Multi-GPU and Hybrid Display Switching

The flicker is often more pronounced on laptops featuring hybrid graphics (such as an integrated Intel/AMD processor paired with a discrete NVIDIA GPU). When Ventoy hands execution to the kernel, the system may query and power up the secondary GPU or switch multiplexers to route the display panel. This physical hardware switching introduces an unavoidable delay and visual flicker before the splash screen stabilizes.
