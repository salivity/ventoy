How Ventoy2Disk.sh Confirms Drives Before Formatting

The Ventoy2Disk.sh shell script includes built-in safeguard mechanisms designed to prevent users from accidentally overwriting important system drives. This article examines how the script inspects the specified target device, presents critical disk metadata to the user, and enforces interactive, multi-step confirmations to verify the drive before executing destructive formatting operations.

Device Validation and Information Gathering

When you run Ventoy2Disk.sh with an install flag (such as -i or -I) and specify a target device (such as /dev/sdb), the script first ensures that the provided parameter points to a valid block device. It verifies that the path exists in /dev and is neither a standard file nor a system partition.

Once validated, the script queries the operating system for hardware details using system utilities such as lsblk, fdisk, or parted. It extracts critical metadata, including:

  • The disk vendor and model name
  • The total storage capacity (size)
  • Existing partition schemes and file systems

Visual Confirmation Prompt

Before writing any data, Ventoy2Disk.sh prints the gathered disk information to the standard terminal output. Displaying the drive's model and size alongside the device node allows the user to visually cross-reference the target path with their intended USB drive, ensuring they have not accidentally targeted an internal hard drive or secondary backup drive.

The Double-Confirmation Safety Check

Unless run with a force-install parameter, the script halts execution and initiates an interactive verification loop:

  1. First Confirmation: The script prints a prominent warning stating that the target device will be formatted and that all existing data will be lost. It then prompts the user to enter y or n to continue.
  2. Second Confirmation: To prevent reflexive or accidental keypresses, the script immediately presents a second prompt asking for confirmation once more (often phrased as "Double check, please confirm again").

If the user enters anything other than y or Y at either prompt, the script aborts immediately without altering the partition table or formatting the storage medium.

Overriding Confirmations

For automated deployments or headless scripts, Ventoy2Disk.sh provides force-mode options (such as the -I flag). When invoked with this option, the interactive user prompts are bypassed. However, in standard interactive operations, the combination of device attribute discovery, explicit data loss warnings, and the dual-prompt requirement serves as the primary barrier against accidental drive destruction.
