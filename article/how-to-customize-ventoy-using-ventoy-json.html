How to Customize Ventoy Using ventoy.json

The ventoy.json configuration file serves as the central control hub for personalizing and extending the functionality of a Ventoy bootable USB drive. By modifying this file, users can transcend standard multiboot options to customize the graphical interface, implement unattended operating system installations, configure live Linux persistence, enforce boot security, and organize boot menus. It replaces complex command-line scripts with a structured JSON format, giving users fine-grained control over how Ventoy behaves across different hardware environments.

Location and Structure

Ventoy does not generate a ventoy.json file by default; it must be created manually. The file must reside inside a dedicated folder named ventoy located on the root of the first partition (the data partition where ISO files are stored), resulting in the path /ventoy/ventoy.json. Because it relies on standard JSON syntax, settings are defined using key-value pairs, nested objects, and arrays.

Visual Themes and Interface Customization

One of the primary uses of ventoy.json is modifying the GRUB-based user interface. Using the theme configuration block, users can:

  • Specify custom GRUB themes, fonts, and background wallpapers.
  • Define screen display resolutions suitable for legacy BIOS and modern UEFI systems.
  • Customize text colors, menu positions, and countdown timer locations.
  • Toggle the display of system architecture indicators and Ventoy version numbers.

Image Aliases and Menu Cleanliness

By default, Ventoy displays the raw filename of any ISO, WIM, or IMG file placed on the drive. Through the menu_alias plugin, ventoy.json allows users to assign clean, recognizable display names without renaming the underlying files. Additionally, the control section can be used to hide specific file extensions, sort files alphabetically or by modification date, and set default boot options with tailored countdown timers.

Persistence Configuration

For live Linux distributions, Ventoy enables data retention across reboots through its persistence plugin. In ventoy.json, users map specific ISO images to pre-allocated persistence image files (such as .dat files). When the specified Linux distribution boots, Ventoy automatically mounts the persistence file, allowing changes, installed packages, and personal files to be saved permanently.

Automated Installations

The auto_install block links ISO files directly to unattended installation scripts, such as unattend.xml for Windows or Kickstart/Preseed files for Linux. When booting an installation medium, Ventoy injects the corresponding answer file into the setup process, enabling entirely hands-off operating system deployments without modifying the original ISO images.

Security and Access Control

The password plugin provides security controls for environments where unauthorized booting must be restricted. Administrators can define a global password required to enter the Ventoy menu, or set individual passwords for specific ISO files. Passwords can be stored as plain text or as cryptographic hashes (such as SHA-256) for increased security.
