How to Boot Ventoy USB in QEMU with KVM

Testing a bootable Ventoy USB drive inside a virtual machine allows you to verify ISO configurations and boot options without rebooting your physical machine. This guide provides the exact QEMU command-line string needed to test a physical Ventoy USB flash drive using hardware acceleration via Kernel-based Virtual Machine (KVM) on Linux.

The QEMU Command String

To launch your Ventoy USB drive in QEMU with KVM, run the following command in your terminal, replacing /dev/sdX with the actual device identifier of your USB drive (for example, /dev/sdb):

sudo qemu-system-x86_64 -enable-kvm -m 2048 -smp 2 -drive file=/dev/sdX,format=raw

Parameter Breakdown

  • sudo: Required to grant QEMU direct read access to the raw storage device.
  • qemu-system-x86_64: The QEMU binary targeting 64-bit x86 hardware.
  • -enable-kvm: Enables KVM hardware acceleration, allowing the virtual machine to run at near-native speeds.
  • -m 2048: Allocates 2048 MB (2 GB) of RAM to the virtual machine, which is sufficient for loading Ventoy and testing lightweight boot environments.
  • -smp 2: Allocates 2 virtual CPU cores to ensure responsive performance.
  • -drive file=/dev/sdX,format=raw: Mounts the entire physical disk as a raw image directly into the virtual machine.

Testing with UEFI Support

By default, the standard command boots into legacy BIOS mode. If your Ventoy setup or the target ISOs rely on UEFI, add the OVMF firmware path to the command:

sudo qemu-system-x86_64 -enable-kvm -m 2048 -smp 2 -bios /usr/share/ovmf/OVMF.fd -drive file=/dev/sdX,format=raw

Ensure the specified path to OVMF.fd matches the location of the package installed on your Linux distribution (commonly found in /usr/share/ovmf/ or /usr/share/edk2-ovmf/).
