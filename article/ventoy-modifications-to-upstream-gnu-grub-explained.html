Ventoy Modifications to Upstream GNU GRUB Explained

Ventoy has redefined the creation of bootable USB drives by allowing users to boot directly from ISO, WIM, IMG, and VHD files without extracting them. At the core of this functionality lies a heavily patched version of upstream GNU GRUB 2. While standard GRUB can loopback-mount an ISO to read its contents, it cannot natively sustain that virtual disk representation once an operating system kernel takes control of hardware. To bridge this gap, the Ventoy project introduced substantial low-level modifications to GRUB's core engine, device abstraction layers, and memory management.

Real-Time Virtual Disk Emulation

Standard GRUB provides temporary file mapping, but it drops these virtual mappings as soon as the payload execution begins. Ventoy implements custom runtime disk virtualization:

  • Legacy BIOS (INT 13h Hooking): Ventoy patches GRUB to hook the BIOS interrupt INT 13h. It constructs a virtual disk table in reserved conventional memory, routing disk read queries for the virtual ISO to the actual contiguous sectors on the underlying physical drive.
  • UEFI Runtime Services & Block I/O: In UEFI environments, Ventoy introduces custom EFI drivers within GRUB that install synthetic EFI_BLOCK_IO_PROTOCOL instances. This fools the bootloader into recognizing the virtual ISO image as a standard, physical hardware disk connected via the system bus.

Runtime OS Bootloader Interception

One of the most complex additions Ventoy makes to GRUB is the ability to patch OS bootloaders on the fly as they are loaded into memory:

  • Windows Support: Ventoy intercepts the Windows boot pipeline (bootmgr and winload.efi). GRUB is modified to patch memory tables to load an in-memory virtual disk driver (ventoy.sys), ensuring Windows setup can find its installation media without needing a dedicated physical CD/DVD drive.
  • Linux Initramfs Injection: Upstream GRUB passes command-line parameters to the Linux kernel. Ventoy modifies GRUB's memory preparation steps to dynamically inject a custom initramfs hook alongside the OS's native initramfs. This injected script runs during early user-space initialization to mount the parent partition and map the ISO file to a loop device before the main root filesystem mounts.

Enhanced Filesystem Drivers

Upstream GNU GRUB historically lacked stable, performant write and read capabilities for certain modern filesystems commonly used on high-capacity external drives. Ventoy introduces optimized, embedded drivers directly into the GRUB image:

  • Robust exFAT Implementation: Ventoy integrates heavily modified, read-optimized exFAT drivers that allow GRUB to reliably locate, read, and calculate fragment sectors for files exceeding 4 GB.
  • NTFS Performance Tweaks: Upstream NTFS drivers inside GRUB were rewritten or optimized to minimize seek times when parsing multi-gigabyte files split across non-contiguous sectors.

Dynamic Image Enumeration and Menu Building

Standard GRUB relies on a static grub.cfg file generated ahead of time. Ventoy replaces this logic with custom modules:

  • Instead of reading hardcoded entries, Ventoy adds core modules that scan directories in real time, extract metadata (OS type, architecture, version) directly from binary headers inside ISO/WIM files, and populate dynamic menus in memory.
  • It embeds custom JSON parsers inside GRUB to read configuration parameters directly from ventoy.json, allowing theme changes, menu alias configurations, and image blacklisting/whitelisting without compiling or rewriting boot scripts.

Secure Boot and Chainloading Architecture

Ventoy alters standard GRUB authentication mechanisms to function under UEFI Secure Boot constraints. It embeds a custom certificate enrollment mechanism and patches GRUB’s verification modules. When booting, Ventoy’s modified GRUB utilizes a custom shim loader that manages MokList registrations directly, preventing standard signature failure exceptions when chainloading third-party, unsigned Linux kernels or legacy Windows environments.
