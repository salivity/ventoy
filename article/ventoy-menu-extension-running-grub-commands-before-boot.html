Ventoy Menu Extension: Running GRUB Commands Before Boot

Ventoy relies on GRUB2 as its core bootloader, which determines how custom menu entries and commands are handled prior to booting an operating system. While Ventoy's JSON-based menu plugins only manipulate visual presentation and metadata, Ventoy's custom menu extension mechanism allows the execution of arbitrary GRUB commands before boot. Understanding the distinction between JSON configuration plugins and native GRUB script extensions is essential for properly configuring custom boot behavior.

JSON Menu Plugins vs. GRUB Script Extensions

Ventoy organizes its customization features into two separate categories:

  1. JSON-Based Menu Plugins: Configurations defined in /ventoy/ventoy.json—such as menu_alias, menu_class, and menu_tip—are strictly declarative. They allow users to rename entries, assign icons, or display hints. These plugins parse static strings and do not evaluate, interpret, or execute arbitrary GRUB commands.
  2. GRUB Menu Extensions (ventoy_grub.cfg): Ventoy provides a dedicated extension mechanism through a user-defined script located at /ventoy/ventoy_grub.cfg. This file is evaluated directly by the underlying GRUB2 shell when accessing the custom boot menu (via the F6 key or automatic configuration).

Executing Arbitrary Commands via ventoy_grub.cfg

Because ventoy_grub.cfg interfaces directly with GRUB2, it provides full access to GRUB's scripting environment. Users can write standard GRUB syntax to execute arbitrary commands before loading a kernel or chainloading an image.

Capabilities supported in this environment include:

  • Environment Variables: Defining, modifying, and exporting GRUB environment variables using set and unset.
  • Module Loading: Dynamically inserting GRUB modules with insmod to add filesystem drivers, network capabilities, or cryptographic functions.
  • Hardware Detection and Configuration: Querying system state, adjusting video modes via set gfxmode, or interacting with PCI devices.
  • Control Structures: Executing conditional logic (if, then, else) and loops directly in the pre-boot phase.
  • Custom Boot Routines: Manually specifying linux, initrd, or chainloader routines with custom kernel parameters rather than relying on Ventoy's automated ISO processing.

Execution Scope and Limitations

While arbitrary commands can run inside custom menu entries defined in ventoy_grub.cfg, they execute within the context and security boundaries of the GRUB2 runtime environment.

  • Commands execute in real mode or protected/long mode depending on the GRUB architecture (BIOS vs. UEFI), prior to the handoff to the OS kernel.
  • Standard Ventoy automated ISO boots operate through Ventoy's internal scripts. Modifying the launch parameters of Ventoy’s default ISO list requires the Boot Configuration Replace plugin or custom GRUB scripting, rather than JSON metadata entries.
  • Secure Boot constraints apply when Ventoy Secure Boot support is enabled, potentially restricting unsigned module loading or specific low-level memory operations.
