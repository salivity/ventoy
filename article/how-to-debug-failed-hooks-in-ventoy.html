How to Debug Failed Hooks in Ventoy

When custom scripts, injection plugins, or automated installation hooks fail during the boot process in Ventoy, identifying the root cause requires enabling detailed runtime output. This article details the specific debugging flag—VTOY_DEBUG—that must be toggled, explains how it exposes hook failure information, and provides the step-by-step methods to activate it either persistently or temporarily during boot.

The Required Debug Flag: VTOY_DEBUG

To troubleshoot and diagnose failed hooks in Ventoy, the flag that must be toggled is VTOY_DEBUG. By default, Ventoy suppresses internal hook execution logs and shell outputs to provide a clean, seamless boot experience. Enabling VTOY_DEBUG forces Ventoy to run hooks in verbose mode, print standard output and standard error to the console, and pause execution upon encountering critical script failures.

Method 1: Enabling via the Global Control Plugin (Persistent)

The standard way to enable the debug flag across reboots is by modifying the ventoy.json configuration file located in the ventoy directory on the first partition of the USB drive.

  1. Open or create ventoy/ventoy.json on the Ventoy USB drive.
  2. Add or update the control block with the VTOY_DEBUG parameter set to "1":
{
    "control": [
        {
            "VTOY_DEBUG": "1"
        }
    ]
}
  1. Save the file and reboot your machine using the Ventoy drive.

Method 2: Enabling via the GRUB Command Line (Temporary)

If you need to diagnose a failed hook without editing configuration files, you can toggle the flag directly from the Ventoy boot menu:

  1. At the main Ventoy boot screen, press c to drop into the GRUB command shell.
  2. Enter the following command to set the variable: 
    set VTOY_DEBUG=1
  3. Press Esc to return to the menu and launch your target ISO.

Diagnosing Hook Failures

With VTOY_DEBUG set to 1:

  • Ventoy prints hook discovery and execution steps line by line before handing control to the kernel.
  • Syntax errors, missing dependencies, or path mismatches in custom hook scripts (such as those used in injection plugins or unattended installation XML/preseed scripts) are explicitly displayed on the screen.
  • Execution will prompt you or pause at breakpoints, allowing you to record specific exit codes and error strings.
