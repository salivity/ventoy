How Ventoy Resolution Plugin Forces Screen Resolution

The Ventoy resolution plugin allows users to bypass automatic display detection and enforce a specific screen resolution during boot. By defining explicit dimensions in the ventoy.json configuration file, Ventoy instructs its underlying bootloader to switch the display mode before rendering the graphical user interface. This article explains the technical mechanism behind how Ventoy forces this resolution across both legacy BIOS and modern UEFI systems.

Ventoy relies on GRUB2 as its core boot environment. Under default conditions, GRUB2 attempts to automatically determine the screen resolution via display auto-detection, which can occasionally result in distorted interfaces, unsupported aspect ratios, or low fallback resolutions. When you configure the resolution plugin (typically defined through the theme configuration or resolution properties in /ventoy/ventoy.json), Ventoy explicitly sets GRUB's internal gfxmode variable to your chosen pixel dimensions (such as 1920x1080 or 1024x768).

To apply the requested resolution, Ventoy interfaces directly with the host machine's low-level firmware:

  1. UEFI Systems (GOP): On modern UEFI hardware, Ventoy queries the Graphics Output Protocol (GOP). The GOP driver provides a list of pre-initialized display modes supported by the video card and monitor. When a forced resolution is set, Ventoy searches the GOP mode list for a match corresponding to the specified width, height, and color depth. If found, it calls the SetMode function of the GOP interface to switch the active framebuffer directly to that mode.

  2. Legacy BIOS Systems (VBE): On older BIOS firmware, Ventoy uses the VESA BIOS Extensions (VBE). It queries the VBE interface for available video modes, identifies the mode number corresponding to the forced resolution, and triggers a BIOS interrupt (INT 10h) to set the requested display state.

Because Ventoy interfaces with hardware via firmware standards rather than native operating system graphics drivers, it cannot force an arbitrary resolution that the underlying video firmware does not support. If the hardware supports the requested mode, the display adapts immediately, rendering the Ventoy boot menu, backgrounds, and fonts at the exact pixel dimensions defined. If the defined resolution is not exposed by the GOP or VBE tables, the bootloader safely ignores the parameter and reverts to a safe fallback resolution to prevent a blank screen.
