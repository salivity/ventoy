How Ventoy Handles Hidden Files and macOS Dotfiles

This article provides an overview of how the Ventoy bootable USB utility detects and manages hidden system files and metadata dotfiles, particularly those generated by macOS. Operating systems like macOS automatically generate hidden resource files (such as ._* and .DS_Store) on external drives formatted with exFAT or FAT32. Below, we examine the internal scanning mechanisms Ventoy uses to filter out these non-bootable artifacts, how file validation prevents corrupt boot entries, and how users can further customize scanning behaviors via configuration files.

Automatic Filtering of Dotfiles

Ventoy operates by dynamically scanning the partitions of a USB drive for supported bootable image formats, including ISO, WIM, IMG, VHD, and EFI files. When macOS interacts with non-native file systems like exFAT or FAT32, it creates "AppleDouble" companion files that begin with ._ (for example, ._ubuntu.iso) to store extended attributes and resource forks. It also generates .DS_Store files to preserve folder view options.

To keep the boot menu functional and clean, Ventoy applies built-in string checks during its directory traversal routine. Any file or directory starting with a period (.) is treated as a hidden Unix-style file and is ignored by default. As a result, files like ._ubuntu.iso are filtered out early in the file enumeration process and are not presented in the boot selection list.

Image Header Verification

Even if an auxiliary file bypasses prefix filtering—such as an improperly named file or a file where the hidden attribute flag behaves inconsistently across filesystem implementations—Ventoy does not rely solely on file extensions.

Before adding any detected item to the bootable list, Ventoy inspects the magic bytes and header structures of the file. A genuine ISO or WIM file has distinct structural headers. Because macOS AppleDouble files contain only binary metadata rather than valid partition tables, file system signatures, or boot sectors, they automatically fail Ventoy's structural integrity checks and are discarded as unbootable.

Advanced Control with ventoy.json

Users who want granular control over how Ventoy parses directories and files can customize the search behavior using the ventoy.json configuration file, located in the ventoy directory on the drive's primary partition.

  1. Restricting Search Paths: By setting the VTOY_DEFAULT_SEARCH_ROOT parameter, you can instruct Ventoy to search only a specific directory (such as /ISOs) rather than the root directory, preventing it from scanning systemic folders where operating systems dump metadata.
  2. Directory Exclusion: The autosel or search filters allow users to ignore designated directories entirely. If macOS creates system directories like .Spotlight-V100 or .fseventsd, Ventoy ignores them through standard directory-skipping parameters.

Manual Cleanup on macOS

While Ventoy prevents dotfiles from cluttering the boot menu, these files still consume directory entries and storage space on the USB drive. macOS users can cleanly unmount drives and strip metadata before unplugging the drive by executing the native dot_clean utility in the terminal:

dot_clean /Volumes/VentoyDriveName

Executing this command merges or removes the ._ files across the specified volume, ensuring the file tree remains clean across all operating systems.
