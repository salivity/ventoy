Reporting Ventoy Hardware Compatibility Issues

When encountering hardware-specific boot failures or quirks with Ventoy, reporting the issue accurately to the developers is essential for a resolution. This article outlines the specific diagnostic data, system configurations, and log files required by the Ventoy development team to identify and resolve hardware compatibility bugs effectively.

1. Ventoy Version and Installation Details

You must provide the exact version and setup parameters of the Ventoy installation running on your drive:

  • Ventoy Version: The exact release number (e.g., v1.0.97).
  • Installation Method: The operating system used to install or update Ventoy (e.g., Windows 11, Ubuntu 22.04) and the tool used (Ventoy2Disk GUI, CLI, or WebUI).
  • Partition Style: Whether the USB drive is formatted using MBR or GPT.

2. Host Machine Hardware Specifications

Because compatibility issues often trace back to proprietary firmware or unique chipsets, include:

  • Device Manufacturer and Model: The complete model name/number of the PC, laptop, or motherboard (e.g., Lenovo ThinkPad T14 Gen 2, ASUS ROG STRIX B550-F).
  • Processor Architecture: CPU type and architecture (x86_64, IA32, ARM64, or MIPS64).
  • Graphics Hardware: Integrated or discrete GPU details (e.g., Intel Iris Xe, NVIDIA RTX 3060).

3. BIOS/UEFI Firmware Configuration

Ventoy operates at the firmware level, making boot environment settings critical:

  • Boot Mode: Specify whether the machine is booting in Legacy BIOS mode or UEFI mode.
  • Secure Boot Status: State whether Secure Boot is enabled or disabled in the system firmware.
  • Firmware Version: The current BIOS/UEFI version installed on the motherboard.

4. Storage Media Details

Hardware issues can stem from the USB controller or the drive itself:

  • Drive Specifications: The make, model, capacity, and interface of the storage medium (e.g., SanDisk Ultra 64GB USB 3.0, Samsung T7 1TB NVMe SSD).
  • Port Used: Whether the drive is plugged directly into a USB 2.0, USB 3.0/3.1 port, or through a USB hub/docking station.

5. ISO or Image File Information

If the problem occurs when loading a specific operating system image, detail:

  • Image Name and Version: The exact file name and distribution version (e.g., archlinux-2023.10.01-x86_64.iso).
  • Checksum: The SHA-256 or MD5 hash of the ISO file to confirm the image is not corrupted.
  • Download Source: The official link where the image was acquired.
  • Secondary Verification: Whether the same ISO boots successfully on the same machine using a traditional single-boot tool (like Rufus or Etcher).

6. Failure Symptoms and Diagnostic Logs

Clear descriptions and visual or file-based evidence allow developers to pinpoint where the boot process halts:

  • Exact Point of Failure: State whether the failure occurs during the initial Ventoy menu load, after selecting an ISO, or during the secondary OS bootloader phase.
  • Error Messages: Transcribe any visible error codes or messages verbatim.
  • Screen Output: Provide clear, high-resolution photographs of the screen if it freezes, reboots, or displays kernel panics/BSODs.
  • Ventoy Log Files: Attach the log.txt file located in the Ventoy installation directory if the issue occurred during the initial drive creation or update process.
