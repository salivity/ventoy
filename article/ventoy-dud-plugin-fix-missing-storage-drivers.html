Ventoy DUD Plugin: Fix Missing Storage Drivers

Installing modern enterprise Linux distributions on specialized hardware often fails when the installer lacks native drivers for proprietary RAID cards, SAS controllers, or modern NVMe drives. The Ventoy Driver Update Disk (DUD) plugin resolves this issue by automatically injecting manufacturer-supplied driver packages into the operating system installer during boot. By associating specific driver image files with targeted OS images, the plugin enables the operating system to detect and configure storage devices without requiring permanent modification of the base installation ISO.

The Storage Driver Problem During OS Installation

Enterprise operating system installers—such as Red Hat Enterprise Linux, CentOS, Rocky Linux, Oracle Linux, and SUSE—rely on a generic kernel to bootstrap the setup environment. When hardware features a newer or proprietary storage controller (such as modern Broadcom MegaRAID, Dell PERC, or Microsemi Adaptec adapters), the installation kernel fails to recognize the attached drives. The installer halts with a "No storage devices found" error, preventing system deployment.

Traditionally, addressing this required either:

  • Rebuilding the installation ISO to include the missing kernel modules (.ko).
  • Creating a separate physical USB drive containing the Driver Update Disk and manually specifying boot parameters like inst.dd during bootloader selection.

How the Ventoy DUD Plugin Operates

The Ventoy DUD plugin automates the delivery of Driver Update Disks via software configuration. It functions through a three-step mechanism:

1. Configuration and Association

Ventoy utilizes a centralized configuration file located at /ventoy/ventoy.json on the USB drive. Within the "dud" object, administrators map specific ISO files to their corresponding driver image files (which typically end in .iso, .img, or .dud).

Multiple drivers can be mapped to a single ISO, allowing complex environments to load network and storage drivers simultaneously.

{
    "dud": [
        {
            "image": "/ISO/Rocky-9.3-x86_64-dvd.iso",
            "dud": "/driver/megaraid_sas.iso"
        }
    ]
}

2. Virtual Disk Presentation and Parameter Injection

When the user boots an ISO configured with the DUD plugin:

  • Ventoy reads the ventoy.json mapping.
  • It loads the specified driver image into system memory.
  • Ventoy dynamically intercepts the bootloader configuration (such as GRUB) and appends the necessary kernel command-line arguments (for example, inst.dd in Red Hat-family installers) pointing directly to the virtual driver disk location in memory.

3. Execution by the Installer

Once the Linux kernel boots into the installation environment:

  • The OS installer's driver detection framework (such as Anaconda or YaST) processes the injected parameters.
  • The installer mounts the driver disk, locates the signed kernel module compatible with the running kernel version, and inserts it via modprobe.
  • With the driver active, the storage controller initializes, exposing the logical drives or RAID arrays to the partitioning utility.

By decoupling the driver payload from the installation medium, the Ventoy DUD plugin allows clean, automated storage initialization while keeping base OS images fully unmodified.
