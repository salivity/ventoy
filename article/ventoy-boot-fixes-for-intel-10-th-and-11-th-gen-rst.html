Ventoy Boot Fixes for Intel 10th and 11th Gen RST

This article explains why systems equipped with Intel 10th and 11th Generation processors encounter boot failures when Intel Rapid Storage Technology (RST) or Volume Management Device (VMD) is active, and details how the Ventoy bootloader resolves these firmware bugs to ensure stable boot and OS installation.

The Intel 10th and 11th Gen RST Issue

With the introduction of Intel 10th Generation (Ice Lake/Comet Lake) and 11th Generation (Tiger Lake/Rocket Lake) architectures, Intel integrated the Intel VMD (Volume Management Device) controller directly into the CPU to manage NVMe storage. When Intel RST/VMD is enabled in the motherboard firmware, standard NVMe drives are hidden behind the RST/VMD controller interface rather than exposed as standard PCI NVMe devices.

Many motherboard manufacturers shipped UEFI firmware versions containing buggy implementation hooks for these controllers. During standard UEFI boot routines, attempts to enumerate drives through standard UEFI ConnectController protocols cause system freezes, black screens, or failure to recognize any physical storage drives.

How Ventoy Bypasses Controller Lockups

Ventoy resolves these hardware-firmware conflicts through low-level UEFI environment patches and optimized controller initialization routines:

  1. Non-Blocking UEFI Device Enumeration: Ventoy modifies how standard UEFI boot services interact with the PCI bus. Instead of relying on buggy vendor-provided EFI drivers that trigger fatal exceptions during RST discovery, Ventoy intercepts and safely polls disk handles to identify boot media without locking the system bus.
  2. Virtual Disk Emulation Isolation: Ventoy mounts ISO images directly in system memory using virtual device handles. By keeping the boot environment independent of the motherboard's native drive mapping early in the execution flow, Ventoy avoids invoking the problematic RST EFI drivers until necessary.
  3. Safe Chainloading: When booting standard boot managers (such as Windows Boot Manager or GRUB2), Ventoy cleans up its temporary hooks and passes control using compliant handoff states that prevent the CPU from entering infinite wait-states caused by the VMD controller.

OS-Level Storage Driver Integration

Even if the bootloader successfully loads an operating system installer, the installer itself might fail to detect storage drives managed by an RST/VMD controller. Ventoy helps bridge this gap using the following mechanisms:

  • Auto-Injection Plugins: Ventoy supports an injection plugin architecture via ventoy.json. Users can configure Ventoy to automatically inject the necessary Intel RST VMD F6 storage drivers into Windows PE or the Windows Setup environment dynamically, allowing the installer to see drives without needing to permanently slipstream drivers into the source ISO.
  • Linux Kernel Compatibility: For modern Linux distributions, Ventoy ensures that appropriate initramfs parameters can be passed so that the intel-vmd kernel module loads properly during the early userspace boot phase.

BIOS Recommendations for Difficult Firmware

While Ventoy includes internal fixes to boot successfully on Intel 10th and 11th Gen systems, severe vendor firmware bugs may still block downstream OS installers. In these specific edge cases, switching the SATA/NVMe controller mode from Intel RST Premium / VMD to AHCI / NVMe standard in the motherboard BIOS eliminates the proprietary RST layer entirely, allowing direct kernel access to all installed drives.
