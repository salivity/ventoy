How Ventoy Detects Bootable vs Data ISOs

Ventoy is a popular open-source utility that enables users to boot directly from ISO files placed on a USB drive without requiring continuous reformatting. To determine whether an ISO file is capable of booting an operating system or is simply a plain data archive, Ventoy inspects the internal structure of the file rather than relying on file extensions or names. It verifies the presence of specific boot specifications—predominantly the El Torito standard—alongside target architecture headers and recognized bootloader configurations.

Inspection of the ISO 9660 and El Torito Standard

Standard data CD/DVD image files utilize the ISO 9660 or UDF (Universal Disk Format) filesystem. When an ISO is created solely for storing data, it contains standard Primary and Supplementary Volume Descriptors starting at sector 16 (offset 0x8000).

A bootable ISO, however, implements the El Torito Bootable CD-ROM Format specification. Ventoy inspects sector 17 (offset 0x8800) for a Boot Record Volume Descriptor. This descriptor contains:

  • The identifier string "EL TORITO SPECIFICATION".
  • A pointer pointing directly to the LBA (Logical Block Addressing) of the Boot Catalog.

If this descriptor is absent or corrupted, Ventoy recognizes the file as a non-bootable, standard data archive.

Evaluating the Boot Catalog

Once Ventoy locates the Boot Catalog, it analyzes the catalog entries to verify their validity and determine the target boot platform:

  1. Validation Entry: Ventoy verifies the initial header (checking for the 0x55AA signature) to ensure the catalog is genuine.
  2. Initial/Default Entry (Legacy BIOS): It checks for entries assigned to Platform ID 0x00 (x86 architecture) with an active boot indicator (0x88). This entry specifies the location of the initial boot code (such as a hard disk or floppy emulation image, or a "no emulation" loader).
  3. Section Headers (UEFI Boot): For UEFI systems, Ventoy checks for Section Header Entries defining Platform ID 0xEF (EFI). These entries point to a FAT-formatted disk image inside the ISO containing the EFI system binaries (such as /EFI/BOOT/BOOTX64.EFI).

If an ISO file lacks valid boot records for either Legacy BIOS or UEFI within the catalog, it cannot be initiated as a live operating system.

Bootloader Identification and Hooking

Simply knowing an ISO has an El Torito descriptor is not always enough for modern hybrid images. Ventoy parses the ISO file to identify known boot frameworks. It scans for signatures of specific loaders:

  • Windows: Looks for bootmgr, bootmgr.efi, and Windows Setup structures.
  • Linux: Looks for ISOLINUX (isolinux.bin), GRUB (grub.cfg, core.img), systemd-boot, or Syslinux configurations.
  • macOS / BSD: Inspects filesystems for specific kernel and boot loader conventions.

Because Ventoy works by dynamically mapping ISO contents into memory and hooking runtime disk access functions, it must identify the exact bootloader in use. If an ISO passes the El Torito check but contains no recognizable bootloader architecture, Ventoy cannot inject its disk-mapping drivers.

Treatment of Plain Data Archives

When an ISO file is merely a compressed archive or backup image:

  • It lacks the sector 17 El Torito identifier.
  • It contains no EFI system partition image.
  • It does not contain executable MBR (Master Boot Record) code in sector 0 (common in hybrid ISOs).

While Ventoy will display any file ending in .iso in its graphical file list by default, selecting a plain data ISO results in an immediate notification that the file is not bootable, preventing the host machine from attempting an execution sequence on an invalid payload.
