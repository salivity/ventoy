Ventoy Persistence Image File Formats

This article explores the specific file format and container architecture used by Ventoy to enable persistent storage on live USB drives. It details the outer container formats, the internal filesystem structures utilized by various Linux distributions, and how Ventoy maps these images to maintain your changes across reboots.

The Container Format: Raw Disk Images (.dat / .img)

Ventoy stores persistent data overlays using raw, fixed-size disk image files. These files typically use the .dat or .img extension. The container acts as a virtual block device that mounts alongside the live operating system ISO during the boot process, redirecting read-and-write operations away from the temporary RAM overlay and onto the physical USB drive.

The Internal Filesystem Format

Inside the raw .dat or .img container, Ventoy requires a standard Linux filesystem. The most common format used is:

  • ext4: The default and most recommended filesystem for modern Linux distributions due to its stability, performance, and journaling capabilities.
  • ext3 / ext2: Older revisions of the extended filesystem, supported for legacy systems or environments where journaling overhead needs to be minimized.
  • XFS: Supported by select enterprise-focused distributions like CentOS or Red Hat Enterprise Linux.

Filesystem Labels and OS Compatibility

While the underlying format of the overlay image is standard ext4, the critical requirement for persistent data to function is the filesystem volume label. Different Linux distributions expect specific labels inside the image to detect the persistent overlay:

  • Ubuntu, Linux Mint, and derivatives: Traditionally require the label casper-rw (or writable for newer Ubuntu versions using cloud-init/systemd based persistence).
  • Debian, Kali Linux, and Parrot OS: Require the label persistence.
  • Arch Linux and derivatives: Require the label cowspace.
  • Fedora: Uses standard device labels like LIVE-RW.

Creating the Persistence File

Ventoy provides a dedicated script called CreatePersistentImg.sh (or CreatePersistentImg.exe for Windows) within its plugin tools. This utility:

  1. Allocates a blank raw file of a specified size (e.g., 4GB).
  2. Formats the inner space with the selected filesystem (typically ext4).
  3. Writes the required label so the OS kernel recognizers the persistence layer at boot.

Once generated, the file is placed on the USB drive and mapped to the corresponding ISO file using Ventoy's configuration file (ventoy.json).
