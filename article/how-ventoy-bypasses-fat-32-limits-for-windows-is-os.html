How Ventoy Bypasses FAT32 Limits for Windows ISOs

Modern Windows installation images frequently exceed the 4GB file size limit imposed by the legacy FAT32 file system, creating bootable media challenges. Ventoy solves this problem through an intelligent dual-partition layout, native support for modern file systems, and a driver-injection mechanism that mounts ISOs dynamically. Rather than extracting files onto a single FAT32 partition or splitting massive image files, Ventoy isolates the boot environment from the storage environment, allowing operating system installers to read files of any size without restriction.

The Dual-Partition Architecture

When Ventoy formats a USB drive, it creates two distinct partitions rather than a single unified space:

  1. Partition 1 (Data Partition): This is the large storage area visible to the user. By default, Ventoy formats this partition using exFAT, though users can also choose NTFS, ext4, or other modern file systems. Because these file systems have maximum file size thresholds far beyond multiple terabytes, storing a modern Windows ISO containing a massive install.wim (often exceeding 5GB or 6GB) poses no file size issue.
  2. Partition 2 (VTOYEFI): This is a small, hidden EFI System Partition (ESP) formatted strictly as FAT16 or FAT32. The Unified Extensible Firmware Interface (UEFI) specification universally requires FAT-formatted partitions to locate bootloader files. Ventoy places its bootloader (based on a modified GRUB2 implementation) and necessary core drivers inside this small partition.

By separating the UEFI-compliant bootloader from the storage area, Ventoy guarantees firmware compatibility via Partition 2 while enabling massive file storage on Partition 1.

No File Extraction Required

Traditional bootable USB creation tools often extract the contents of a Windows ISO onto the USB drive. When relying on a single FAT32 partition to guarantee universal UEFI boot compatibility, this extraction method fails whenever install.wim exceeds the 4GB ceiling. Other tools address this by splitting the .wim file into smaller .swm chunks using Windows DISM utilities.

Ventoy eliminates extraction entirely. Users copy the intact .iso file directly onto the exFAT or NTFS data partition as a single file, eliminating the risk of write failures or corrupted file splits.

Runtime Hooking and Driver Injection

The primary technical hurdle with booting a raw ISO from an exFAT or NTFS drive is that native Windows Setup environments (Windows PE) do not inherently mount loopback ISOs from external drives during initial setup. Ventoy bypasses this obstacle at runtime:

  1. Bootloader Execution: The UEFI firmware initializes the bootloader located in the FAT32 EFI partition.
  2. ISO Selection: The bootloader loads filesystem drivers (such as an exFAT or NTFS driver) to scan Partition 1 and display a menu of available ISO files.
  3. Environment Hooking: Once a Windows ISO is selected, Ventoy patches the Windows PE boot sequence in memory before handing control over to the Windows kernel.
  4. Virtual Disk Emulation: During Windows setup initialization, a lightweight Ventoy driver is loaded into the Windows PE memory space. This driver mounts the original ISO file from the exFAT partition as a virtual CD/DVD drive.

Because Windows Setup sees the installation media as a mounted optical disc containing standard files, it reads the oversized install.wim directly through its internal filesystem structures without ever encountering a FAT32 size constraint.
