How Ventoy Handles FreeBSD and OpenBSD Images

Ventoy allows users to boot FreeBSD and OpenBSD installation media directly from standard ISO and IMG files without reformatting the USB drive. Because BSD operating systems use fundamentally different bootloaders, kernels, and device-mounting architectures compared to Linux, Ventoy employs specialized bootloader patching, memory mapping, and custom device-injection mechanisms rather than traditional loopback techniques.

The Challenge of Booting BSD on Ventoy

Standard Linux distributions typically boot through a ramdisk (initramfs) where Ventoy hooks into the system, locates the ISO file on the USB filesystem (exFAT, NTFS, or ext4), and creates a loop device that the installer reads as a physical drive.

FreeBSD and OpenBSD do not use a standard Linux initramfs. Their boot processes rely on proprietary secondary bootloaders and monolithic kernels that immediately take over hardware control, discarding BIOS/UEFI virtual disk services unless explicitly instructed or patched.

How Ventoy Boots FreeBSD

Ventoy supports both official FreeBSD .iso and .img installer media through the following process:

  1. Bootloader Interception: When you select a FreeBSD image, Ventoy’s GRUB-based core loads the FreeBSD bootloader (loader.efi under UEFI or loader under legacy BIOS).
  2. Hooking the GEOM Layer: In FreeBSD, storage devices are managed by the GEOM subsystem. Ventoy injects a dedicated driver into the FreeBSD boot stage.
  3. Mounting the Virtual Media: Once the FreeBSD kernel initializes, Ventoy's hooked driver presents the original ISO/IMG file as a memory-backed disk or virtual block device (similar to FreeBSD’s native md memory disk).
  4. Installer Handoff: When bsdinstall launches, it looks for installation sets. Because the Ventoy driver maintains access to the ISO structure, the installer detects the virtual CD/drive normally and proceeds without requiring network-only media.

How Ventoy Boots OpenBSD

OpenBSD has strict hardware validation and does not support standard ISO loopback mounting during runtime. Ventoy handles OpenBSD using an approach tailored to the OpenBSD ramdisk kernel:

  1. Memory Mapping (Memdisk): For OpenBSD installer images (such as install*.iso or miniroot*.img), Ventoy maps the image directly into system RAM. In Legacy BIOS mode, it relies on INT 13h emulation; in UEFI mode, it uses UEFI RAM-disk protocols.
  2. Kernel Execution: Ventoy executes the OpenBSD secondary boot program (boot), which loads the ramdisk installation kernel (bsd.rd).
  3. Installer Limitations and Media Detection: Because OpenBSD’s kernel disables BIOS/UEFI runtime disk emulation after taking control of the hardware, it often loses visibility of the virtual disk holding the installation sets. In such scenarios, the OpenBSD installer runs in RAM, but you may need to point the installer to an HTTP/FTP mirror or an uncompressed partition containing the installation file sets (base*.tgz, etc*.tgz).

Best Practices for BSD on Ventoy

  • Image Formats: Use raw .img files where available, especially for OpenBSD, as they often boot more reliably than hybrid .iso files.
  • Boot Mode: Ensure the machine boots using the firmware mode (UEFI or Legacy BIOS) that matches the target installation image. OpenBSD performs more predictably under native UEFI boot on modern Ventoy versions.
  • Ventoy Memdisk Mode: If a BSD image fails to boot using the normal mode, pressing F1 in Ventoy enables Memdisk mode, which forces the entire image into RAM prior to execution.
