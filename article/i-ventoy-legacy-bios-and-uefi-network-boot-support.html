iVentoy Legacy BIOS and UEFI Network Boot Support

iVentoy provides complete, native network boot support for both legacy BIOS and modern UEFI client machines simultaneously. This article outlines iVentoy's multi-architecture capabilities, details how the platform handles automatic architecture detection during the Preboot Execution Environment (PXE) boot process, and explains the network configuration required to serve diverse client hardware from a single server.

Supported Client Architectures

iVentoy is designed to operate in mixed-hardware environments without requiring separate servers for different firmware types. It natively supports the following client architectures:

  • x86 Legacy BIOS: Standard 32-bit and 64-bit systems utilizing traditional BIOS firmware.
  • x86_64 UEFI: Modern 64-bit UEFI-based personal computers, workstations, and servers.
  • IA32 UEFI: 32-bit UEFI implementations, commonly found on older Intel Atom tablets and low-power devices.
  • ARM64 UEFI: 64-bit ARM-based systems and single-board computers (such as modern ARM servers or supported developer boards).

How iVentoy Detects Firmware Types

When a client initiates a network boot request via PXE, it broadcasts a DHCP Discover packet containing standard DHCP options (specifically Option 93, the Client System Architecture Type).

iVentoy dynamically reads this identifier to determine whether the requesting client is running legacy BIOS or a specific flavor of UEFI. Once identified, iVentoy automatically serves the matching Network Bootstrap Program (NBP)—delivering standard PXE binaries to legacy systems and signed EFI binaries to UEFI clients. Because this process is fully automated, the administrator does not need to manually assign specific boot files to specific MAC addresses.

DHCP Integration Modes

iVentoy can manage both firmware types regardless of your network layout through three distinct operational modes:

  1. Internal DHCP Server: iVentoy acts as the primary DHCP server on an isolated network. It assigns IP addresses and automatically routes BIOS and UEFI clients to their respective boot files.
  2. External DHCP with iVentoy as Proxy (PXE Mode): An existing router or server handles IP address assignment. iVentoy listens to network requests and answers only with PXE boot parameters, distinguishing between BIOS and UEFI automatically without interfering with normal IP distribution.
  3. External DHCP with Option 66/67: If manually configuring an enterprise DHCP server (such as Windows Server DHCP or pfSense), you point the DHCP server to iVentoy's IP address. For mixed environments, your external DHCP server must be configured with vendor class policies to dispatch the correct bootloader filename based on Option 93.

Key Advantages for Mixed Environments

  • Single ISO Repository: You only need to place your ISO files into iVentoy's iso directory once. The software dynamically adapts the boot environment, allowing a single dual-boot ISO (supporting both BIOS and UEFI) to serve either architecture as needed.
  • UEFI Secure Boot Support: iVentoy supports booting UEFI clients even when Secure Boot is enabled, utilizing its own enrollment certificates to maintain security standards across modern endpoints.
  • Zero File Extraction: Unlike traditional PXE setups that require extracting kernel and initrd files for both BIOS and UEFI layouts, iVentoy boots directly from unmodified ISO images across all supported client modes.
