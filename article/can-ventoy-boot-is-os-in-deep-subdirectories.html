Can Ventoy Boot ISOs in Deep Subdirectories?

Ventoy fully supports detecting and booting ISO files located within deeply nested subdirectories on its data partition. By default, the bootable USB solution automatically performs a recursive scan across directories to compile its boot menu, eliminating the need to keep image files exclusively in the root directory. This article explains how Ventoy handles nested folders, directory depth limits, configuration options, and best practices for organizing your ISO library.

Automatic Directory Traversal

When a system boots into Ventoy, the software scans the primary storage partition (typically the first partition formatted as exFAT, NTFS, ext4, or FAT32) for supported image formats, including .iso, .wim, .vhd, and .img.

This scan is recursive, meaning Ventoy automatically looks through parent folders and child subfolders. You can organize your images using logical folder structures, such as:

  • /ISOs/Linux/Ubuntu/ubuntu-22.04.iso
  • /ISOs/Windows/Win11/Win11_English_x64.iso
  • /Utilities/Antivirus/RescueDisk.iso

Ventoy aggregates all discovered files into a single, unified boot menu by default, displaying the file name regardless of its location in the directory tree.

Directory Depth Limits and Configuration

While Ventoy supports nested directories, directory traversal is governed by predefined search limits to prevent long scanning delays or memory issues:

  • Default Search Depth: Ventoy searches subdirectories down to a set depth level automatically. For standard multi-level folder structures, no extra configuration is required.
  • Customizing Search Depth via ventoy.json: If your ISO files are stored extremely deep in a folder hierarchy, you can configure the search depth using the ventoy.json configuration file. Within the control section, the max_search_depth parameter allows you to define how many directory levels Ventoy will traverse during boot initialization.

Example configuration snippet in /ventoy/ventoy.json:

{
    "control": [
        { "max_search_depth": 5 }
    ]
}

Setting this value to an appropriate integer ensures Ventoy parses your deeply nested subfolders without unnecessary overhead.

Tree View Mode

If you store a large number of ISO files in nested folders, a flat list of files in the main menu can become difficult to navigate. Ventoy includes a built-in Tree View mode:

  • Press F3 on the main Ventoy boot screen to toggle Tree View.
  • Tree View replaces the flat list with a navigable directory structure that mirrors your actual folder hierarchy on the USB drive.

Best Practices for Nested Directories in Ventoy

  1. Avoid Extremely Long Paths: Boot environments have memory and string-length limitations. Keep folder names reasonably concise to prevent path truncation.
  2. Avoid Non-Standard Characters: Do not use special symbols, non-ASCII characters, or trailing spaces in folder names. Standard alphanumeric characters, underscores, and hyphens ensure compatibility across both legacy BIOS and UEFI modes.
  3. Exclude Non-Boot Folders: If your USB drive contains personal files alongside ISOs, use the VTOY_DIR_RECYCLE attribute or the ventoy.json file to restrict scanning to specific image directories. Limiting the search scope reduces boot-time scanning delays.
