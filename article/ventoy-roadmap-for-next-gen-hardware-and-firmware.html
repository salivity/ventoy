Ventoy Roadmap for Next-Gen Hardware and Firmware

This article provides an overview of Ventoy's ongoing and projected development roadmap, focusing on its expansion toward emerging hardware architectures and evolving firmware environments. As computing platforms diversify away from standard x86 BIOS architectures toward native UEFI, ARM64, and RISC-V, Ventoy is actively adapting its core multiboot toolchain. Below is a detailed breakdown of how Ventoy plans to support newer CPU architectures, modern firmware standards, and advanced boot ecosystems.

Expansion of Processor Architectures

While Ventoy established its reputation on x86 and x86_64 architectures, hardware diversification has made cross-architecture capability a development priority:

  • ARM64 (AArch64) Stabilization: Ventoy offers initial support for ARM64 UEFI environments, but upcoming milestones target functional parity with x86_64. This involves broader compatibility with ARM-based servers, Windows on ARM hardware, and popular single-board computers (SBCs) that implement standard UEFI implementations.
  • RISC-V Architecture Evaluation: As RISC-V gains traction in developer platforms and embedded systems, Ventoy's development trajectory includes tracking RISC-V EFI specifications. Adaptation relies on maturing GRUB2 RISC-V upstream patches, which will eventually allow Ventoy to mount and boot RISC-V Linux distributions natively.
  • LoongArch Refinements: Initial hooks for the LoongArch architecture have been introduced in recent cycles. Future updates focus on refining chainloading mechanisms and expanding image-type support for distributions targeting this architecture.

Adaptation to Modern Firmware Standards

Legacy BIOS (CSM) is rapidly disappearing from modern motherboards, shifting the boot ecosystem entirely to UEFI:

  • Class 3 and Class 3+ UEFI Support: Modern systems operate exclusively in native UEFI without any Compatibility Support Module (CSM). Future Ventoy updates are optimizing memory allocation, video output protocols (GOP), and native EFI drivers to ensure seamless handoffs without relying on legacy fallbacks.
  • Secure Boot Lifecycle and Key Management: With Microsoft updating revocation lists (DBX) and introducing new certificate authorities, Ventoy's integration with the shim loader and Machine Owner Key (MOK) system is undergoing continuous maintenance. The roadmap focuses on streamlining the initial key-enrollment process to minimize user friction during Secure Boot verification.
  • Alternative Firmware Compatibility: Independent open-source firmware solutions like Coreboot, Libreboot, and Tianocore (EDK II) payloads are increasingly used in privacy-focused hardware. Ventoy's roadmap includes targeted compatibility testing against these firmware stacks to resolve non-standard ACPI table handling and memory mapping issues.

Storage Protocols and Filesystem Hooks

Modern hardware architectures employ high-throughput storage interfaces that require lower-level firmware awareness:

  • Advanced Controller Interfacing: Newer motherboards, particularly enterprise platforms and handheld gaming systems, utilize cutting-edge NVMe specifications and USB4/Thunderbolt controller tunnels. Ventoy continues to update its underlying driver stack to recognize dynamic block devices directly from the pre-boot environment.
  • Direct Virtual Disk Mapping: Ventoy relies on device mapper hooks to present ISO, WIM, and IMG files as physical media to the loaded operating system. As kernel security models become more restrictive, the Ventoy roadmap includes redesigning OS-specific runtime scripts (such as ventoy-ng) to maintain compatibility with modern Linux kernels, Windows 11 updates, and custom hypervisors without tripping kernel integrity protections.
