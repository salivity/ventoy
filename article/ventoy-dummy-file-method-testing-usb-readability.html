Ventoy Dummy File Method: Testing USB Readability

The dummy file method used by Ventoy is a practical verification technique designed to test the readability and physical integrity of storage sectors on a USB drive without formatting or destroying existing data. This article explains how the dummy file approach works, why it is critical for identifying failing sectors or counterfeit USB storage, and how the read verification process ensures that bootable ISO files remain stable and functional during system installations.

Purpose of Sector Testing in Ventoy

USB flash drives, particularly budget or heavily used drives, are susceptible to bad sectors, worn NAND flash cells, and falsified storage capacities. Because Ventoy maps and boots operating system images directly from raw sectors on the storage media, even a single unreadable cluster can cause a boot failure or crash an installation process midway. Testing sector readability guarantees that the drive's memory cells can consistently store and return data without input/output (I/O) timeouts or data corruption.

How the Dummy File Method Works

Rather than executing a destructive surface scan that overwrites the entire partition table and destroys existing ISO files, the dummy file method operates at the filesystem level:

  1. Space Allocation: The method calculates the available free space on the USB flash drive's data partition.
  2. File Generation: A single large file, or a sequence of files, is created to fill the remaining unallocated sectors. These files are populated with predetermined, predictable data streams (such as repeated byte patterns or cryptographically hashed blocks).
  3. Sequential Writing: As these dummy files are written, the operating system's filesystem driver allocates previously unused physical sectors on the NAND flash to accommodate the data.
  4. Sector Readback: Once written, the testing utility reads the dummy files sequentially from start to finish. It compares the read stream against the original pattern or computes a checksum (such as SHA-256 or MD5) to verify data validity.
  5. Safe Deletion: After the read pass is finished, the dummy files are deleted, immediately returning the drive to its original free state without modifying the Ventoy bootloader or any stored boot images.

Identifying Bad Sectors and Counterfeit Drives

The dummy file method effectively reveals two primary hardware faults:

  • Physical Read Errors and Degradation: If the drive controller encounters hardware-level read errors, delays, or I/O failures while reading back the dummy files, it indicates physically degraded sectors that should not be trusted with critical files.
  • Fake Capacity Detection: Counterfeit flash drives report a larger storage size to the operating system than their actual hardware capacity allows. When dummy files exceed the physical flash boundaries, the drive controller typically wraps the write operations around, overwriting early sectors or dropping data entirely. When the readback process fails to match the original checksums, the drive is exposed as counterfeit.

By validating all accessible sectors through harmless dummy data, users can verify drive reliability and ensure that critical system images will boot and install without sector-induced failures.
