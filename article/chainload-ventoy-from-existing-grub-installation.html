Chainload Ventoy from Existing GRUB Installation

Yes, the Ventoy bootloader binary can be successfully chainloaded from an existing GRUB installation. This article explains how the chainloading process works for both UEFI and Legacy BIOS environments, provides the exact configuration entries needed for your grub.cfg file, and details the steps required to locate and boot the Ventoy partition directly from your host system's GRUB menu.

Understanding the Ventoy Drive Layout

When Ventoy formats a storage drive, it splits it into two distinct partitions:

  1. Partition 1 (exFAT, NTFS, or ext4): The primary storage area where ISOs and other boot images reside.
  2. Partition 2 (FAT, typically labeled VTOYEFI): A small, protected partition containing the actual Ventoy bootloader files, GRUB core images, and EFI binaries.

To chainload Ventoy, GRUB must target the bootloader binary located on this second partition.

Chainloading Ventoy in UEFI Mode

In modern UEFI systems, chainloading is reliable because you can target Ventoy's signed EFI binary directly.

1. Identify the Ventoy EFI Partition

Open a terminal and run:

lsblk -f

Locate the partition labeled VTOYEFI (typically partition 2, such as /dev/sdb2) and note its UUID.

2. Add the GRUB Menu Entry

Add the following entry to /etc/grub.d/40_custom on your Linux host:

menuentry "Ventoy Bootloader (UEFI)" {
    insmod part_gpt
    insmod part_msdos
    insmod fat
    insmod chain
    search --no-floppy --fs-uuid --set=root YOUR-VTOYEFI-UUID-HERE
    chainloader /EFI/BOOT/BOOTX64.EFI
}

Note: Replace YOUR-VTOYEFI-UUID-HERE with the actual UUID of the VTOYEFI partition. If booting on 32-bit UEFI or ARM64, adjust the binary name accordingly (e.g., BOOTIA32.EFI or BOOTAA64.EFI).

Chainloading Ventoy in Legacy BIOS / MBR Mode

In Legacy BIOS mode, chainloading involves handing execution over to the Master Boot Record (MBR) or the Volume Boot Record (VBR) of the Ventoy disk.

Menu Entry for Legacy BIOS

Add the following entry to /etc/grub.d/40_custom:

menuentry "Ventoy Bootloader (BIOS)" {
    insmod part_msdos
    insmod ntfs
    insmod fat
    search --no-floppy --fs-uuid --set=root YOUR-VENTOY-DATA-UUID-HERE
    drivemap -s (hd0) ${root}
    chainloader +1
}

Alternatively, if you know the exact drive designator:

menuentry "Ventoy Direct Drive Chainload" {
    set root=(hd1)
    chainloader +1
}

Applying the Changes

After editing /etc/grub.d/40_custom, rebuild your GRUB configuration file:

  • Ubuntu/Debian-based systems: 
    sudo update-grub
  • Fedora/RHEL/Arch-based systems: 
    sudo grub2-mkconfig -o /boot/grub2/grub.cfg

Restart your computer and select the new Ventoy entry from the GRUB menu. GRUB will transfer execution to Ventoy, presenting the standard Ventoy interface listing your available ISO files.
