Ventoy Symlink Support for Duplicate ISO Files

Managing multiple versions or renamed copies of bootable images often leads users to consider symbolic links to save disk space. This article examines whether Ventoy natively supports symbolic links (symlinks) inside its storage partition, explains the underlying technical reasons why symlinks fail during pre-boot operations, and details viable alternatives—such as hard links and native configuration options—to avoid storing duplicate ISO files.

Native Symlink Support in Ventoy

Ventoy does not support native symbolic links for detecting or booting ISO files. If you create a symlink pointing to an ISO image on the Ventoy storage partition, Ventoy's file-scanning routine will either ignore the file entirely or display an entry that fails to load during execution.

This limitation stems from how Ventoy operates:

  • Pre-Boot Environment Constraints: Ventoy relies on a modified GRUB2 core and low-level filesystem drivers to scan directories before an operating system loads. These drivers are designed to locate direct file clusters rather than resolve POSIX symlinks or relative path pointers.
  • Filesystem Incompatibility: By default, Ventoy formats the data partition with exFAT to ensure broad cross-platform compatibility. The exFAT filesystem does not natively support POSIX-style symbolic links. Even when using NTFS, ext4, or Btrfs, the bootloader environment cannot reliably resolve symlink target paths.

The Solution: Using Hard Links

While symbolic links do not work, hard links provide an effective workaround if the storage partition is formatted with a compatible filesystem.

A hard link creates an additional directory entry that points directly to the existing data clusters on disk, bypassing path-resolution logic entirely. To Ventoy, a hard link appears as a distinct, standard file, meaning it can be scanned and booted without issues while consuming zero additional storage space.

To use hard links with Ventoy:

  1. Format the Partition: Reformat the Ventoy storage partition to NTFS (for Windows/Linux cross-compatibility) or ext4 (for Linux-only environments), as exFAT does not support hard links.
  2. Create the Link:
    • Windows (Command Prompt): mklink /H "F:\Target_Copy.iso" "F:\Original_Image.iso"
    • Linux: ln /media/ventoy/Original_Image.iso /media/ventoy/Target_Copy.iso

Managing Duplicate Entries via Configuration

If your primary goal is to present an ISO under multiple names, categories, or menu positions without altering files, Ventoy provides native mechanisms through its configuration plugin (ventoy.json):

  • Menu Aliases: Use the menu_alias plugin to assign user-friendly display labels to ISO files instead of duplicating them to change their display names.
  • Menu Grouping: Use the menu_class plugin to categorize files into custom directories or boot menus without moving the original images.
