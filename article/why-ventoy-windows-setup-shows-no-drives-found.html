Why Ventoy Windows Setup Shows No Drives Found

When installing Windows using a Ventoy multiboot USB drive, encountering the error "No drives were found" is a frequent issue that prevents users from selecting an installation destination. This problem usually does not indicate a defective hard drive or SSD; instead, it is primarily caused by missing storage controller drivers in the standard Windows installer image, specific UEFI/BIOS storage configurations, or outdated Ventoy software. This guide covers the root causes of this error and provides direct methods to resolve it.

Missing Storage Controller Drivers (Intel VMD / AMD RAID)

The most common reason modern systems fail to detect internal drives during Windows installation is the absence of native controller drivers.

Starting with 11th Gen Intel Core processors, many motherboards utilize Intel Volume Management Device (VMD) to manage NVMe drives. Similarly, systems configured with AMD RAID controllers require proprietary drivers. Standard Windows installation ISOs do not bundle these specific storage controller drivers. Consequently, when the Windows installer loads via Ventoy, it cannot communicate with the storage controller, resulting in an empty drive selection screen.

BIOS/UEFI Controller Modes

Factory motherboard settings often have storage modes configured to proprietary setups rather than standard protocols:

  • Intel RST / RAID On: Many pre-built laptops and desktops (such as Dell, HP, or Lenovo) ship with storage set to RAID On or Intel RST (Rapid Storage Technology) mode instead of standard AHCI/NVMe.
  • VMD Controller Enabled: On newer Intel systems, VMD is often enabled by default in the firmware, obfuscating direct NVMe access from general operating system installers.

Without active drivers loaded in Windows PE (the pre-installation environment), Windows cannot interact with drives managed under these modes.

Outdated Ventoy Installation or Driver Injection Glitches

Ventoy uses a background hook to mount the Windows ISO into memory so that setup files remain accessible after the initial boot phase. If the installed version of Ventoy is outdated, it may contain compatibility bugs with newer Windows 11/10 builds or newer hardware chipsets, preventing the storage stack from properly enumerating attached drives.

How to Resolve the Error

Method 1: Load the Storage Controller Driver Manually

  1. Download the appropriate driver from your computer manufacturer’s support site or Intel’s website (e.g., Intel Rapid Storage Technology (RST) Driver with VMD Support).
  2. Extract the driver archive so that raw files (.inf, .sys, and .cat) are visible.
  3. Copy the extracted driver folder onto the root of your Ventoy USB drive.
  4. Boot into the Windows installer through Ventoy and proceed until the "Where do you want to install Windows?" screen appears.
  5. Click Load driver in the bottom-left corner.
  6. Click Browse, navigate to the driver folder on your Ventoy USB, select the relevant .inf file, and confirm. The target drive should immediately become visible.

Method 2: Adjust BIOS/UEFI Settings

If you do not require RAID or Intel Optane acceleration:

  1. Restart your PC and access the BIOS/UEFI menu (typically by pressing F2, F12, Del, or Esc during startup).
  2. Locate the Storage, SATA Operation, or System Configuration menu.
  3. Change the storage mode from RAID On / Intel RST to AHCI / NVMe.
  4. If an option for Intel VMD Technology exists, set it to Disabled.
  5. Save the settings, restart, and boot back into the Windows installer via Ventoy.

Method 3: Update Ventoy

Ensure your Ventoy USB drive has the latest release installed. Connect the drive to a working computer, launch the Ventoy installer utility, and click Update. Updating does not delete the ISO files stored on the drive and ensures maximum compatibility with modern hardware and ISO layouts.
