Does Ventoy Cache JSON Files in Memory During Boot?

This article examines how Ventoy handles its primary configuration file, ventoy.json, during the initial startup process, specifically answering whether the tool caches JSON data in memory. It covers how the underlying GRUB2 environment reads configuration files, the lifecycle of this data in RAM, and the practical implications for users modifying settings on live USB drives.

The Direct Answer

Yes, Ventoy reads and caches the ventoy.json configuration file into memory during the boot process. When a computer boots from a Ventoy USB drive, the system loads Ventoy's modified GRUB2 core into RAM. During initialization, the internal JSON parsing engine reads the /ventoy/ventoy.json file from the physical storage medium, parses the key-value pairs, and stores these structures directly in system memory.

How Ventoy Processes Configuration Files

Ventoy relies on a modular GRUB2 architecture to create its dynamic boot menu. The handling of the JSON configuration follows a specific sequence:

  1. Storage Detection: During early boot, Ventoy mounts the primary file system partition containing the ISOs and the ventoy directory.
  2. File Loading: The bootloader searches for /ventoy/ventoy.json. If found, a custom GRUB C-module reads the file contents into a memory buffer.
  3. Parsing and Structuring: The JSON parser converts the raw text into structured memory objects. These objects control theme parameters, global control plugins, image list options, and menu aliases.
  4. Menu Generation: The boot menu is rendered based on the parsed values held in memory, rather than by querying the physical drive repeatedly.

Why Ventoy Uses In-Memory Caching

Caching the configuration in RAM serves two main technical purposes:

  • Performance: Reading repeatedly from USB flash drives—especially older USB 2.0 drives—introduces input/output latency. Caching the file in RAM ensures the user interface remains responsive when navigating menus, toggling display modes, or switching themes.
  • Storage Independence: Certain Ventoy plugins (such as auto-install scripts or persistence configurations) require fast access to predetermined flags. By keeping parsed definitions in memory, Ventoy reduces read cycles on the flash storage controller.

Memory Lifecycle and Live Modifications

The cached JSON data exists only within the execution context of the bootloader. Because the data resides in volatile memory allocated to GRUB:

  • Handoff to OS: Once a user selects an ISO and the target operating system's kernel assumes control of the hardware, the entire GRUB memory space—including the cached JSON data—is discarded and overwritten by the OS memory manager.
  • On-the-Fly Editing: If a user physically connects to the drive over a network or modifies the JSON file via a live multi-boot environment while the menu is running, the running Ventoy interface will not reflect these changes automatically. Ventoy does not actively poll the disk for configuration changes; it requires a menu reload or a system reboot to re-read and re-cache the updated ventoy.json file.
