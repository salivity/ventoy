Can Ventoy Load Custom ACPI Tables at Boot?

Ventoy does not feature a dedicated, out-of-the-box plugin for automated ACPI table injection, but it is technically capable of loading custom ACPI tables by leveraging its underlying GRUB2 boot environment. While standard ISO boot modes bypass manual table loading, users can inject custom DSDT or SSDT tables by using custom GRUB configurations, command-line execution, or OS-level initramfs injection alongside Ventoy.

Native Support vs. Underlying Capabilities

Ventoy simplifies multi-boot USB creation by dynamically scanning and mapping ISO, WIM, and IMG files. In its standard operating mode, Ventoy's automated loader mounts the ISO and transfers control to the operating system kernel or bootloader without altering firmware tables. Consequently, you will not find a native setting within ventoy.json specifically designated for loading .aml (ACPI Machine Language) files automatically across arbitrary disk images.

However, because Ventoy uses a modified version of GRUB2 to initialize the pre-boot environment, it inherits GRUB2’s native features, including the acpi command.

Loading ACPI Tables via ventoy_grub.cfg

The most reliable way to load custom ACPI tables using Ventoy is through the menu extension plugin. Ventoy allows you to define a secondary GRUB menu by placing a file named ventoy_grub.cfg inside the ventoy directory on the USB drive's primary partition.

Within this custom configuration file, you can utilize GRUB2 syntax to load ACPI tables before starting the target operating system:

menuentry "Boot Linux with Custom ACPI" {
    acpi -m /ventoy/acpi/custom_dsdt.aml
    # Additional kernel and initrd loading directives
}

When GRUB executes the acpi command, it overrides or appends the specified ACPI tables in system memory before the operating system kernel initializes.

Practical Limitations with ISO Files

Using GRUB2 commands to override ACPI tables presents challenges when combined with Ventoy’s standard ISO booting mechanism:

  1. Chainloading Overwrite: When Ventoy hooks into an ISO file's internal EFI bootloader (such as bootx64.efi for Windows or Linux distros), the secondary bootloader may re-read system ACPI tables directly from UEFI firmware, ignoring or overwriting the pre-boot memory modifications made by GRUB.
  2. OS-Specific Handling: For Windows installations, custom ACPI tables are rarely accepted from raw pre-boot hooks unless secure boot is disabled and specific test-signing or kernel debugger flags are active.

Alternative Approaches on a Ventoy Drive

If your goal is to test or run hardware configurations that require custom ACPI tables (such as fixing broken DSDT tables on specific laptops), consider these alternatives:

  • Linux Initrd Prepend: Instead of relying on Ventoy to load the ACPI table directly into firmware memory, build an uncompressed CPIO archive containing your compiled .aml file located at kernel/firmware/acpi/. Configure your Linux boot loader or Ventoy custom entry to load this archive as the first initrd. The Linux kernel will automatically override its internal ACPI representation.
  • Chainloading OpenCore or Clover: Place an EFI-based bootloader such as OpenCore onto the Ventoy partition. You can boot into Ventoy, chainload OpenCore, and let OpenCore perform robust, runtime ACPI patching (DSDT/SSDT injection) before launching Windows, macOS, or Linux.
