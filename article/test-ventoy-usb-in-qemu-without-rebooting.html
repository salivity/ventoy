Test Ventoy USB in QEMU Without Rebooting

Testing a bootable Ventoy USB drive typically requires rebooting your physical machine, which interrupts your ongoing work. By using QEMU, a lightweight and open-source emulator, you can launch and verify your Ventoy drive in a virtualized window directly from your desktop. This guide covers how to identify your drive, install necessary tools, and boot the USB in both Legacy BIOS and modern UEFI modes on Linux and Windows.

1. Identify Your USB Drive

Before running QEMU, determine the exact device identifier assigned to your Ventoy USB drive.

  • Linux: Open a terminal and run:

    lsblk

    Look for your USB stick by its capacity (e.g., sdb or sdc). You must target the entire disk device (such as /dev/sdb), not an individual partition (such as /dev/sdb1).

  • Windows: Open PowerShell as Administrator and run:

    Get-Disk

    Note the Number corresponding to your USB drive. In QEMU, disk 1 maps to \\.\PhysicalDrive1.

2. Booting on Linux

Ensure QEMU is installed on your distribution:

  • Debian/Ubuntu: sudo apt install qemu-system-x86 ovmf
  • Fedora: sudo dnf install qemu-system-x86 edk2-ovmf
  • Arch Linux: sudo pacman -S qemu-desktop edk2-ovmf

Legacy BIOS Boot

Run the following command, replacing /dev/sdX with your actual device:

sudo qemu-system-x86_64 -enable-kvm -m 2048 -drive file=/dev/sdX,format=raw,cache=none
  • -enable-kvm: Activates hardware acceleration for native speed.
  • -m 2048: Allocates 2 GB of RAM to the virtual machine.
  • -drive file=/dev/sdX,format=raw,cache=none: Points directly to the raw USB drive.

UEFI Boot

Ventoy supports UEFI boot configurations. To test UEFI menus, pass the OVMF firmware path to QEMU:

sudo qemu-system-x86_64 -enable-kvm -m 2048 -bios /usr/share/ovmf/OVMF.fd -drive file=/dev/sdX,format=raw,cache=none

(Note: On some distributions like Arch or Fedora, the firmware path may be /usr/share/edk2-ovmf/x64/OVMF.fd or /usr/share/edk2/ovmf/OVMF.fd.)

3. Booting on Windows

  1. Download and install QEMU for Windows.
  2. Open Command Prompt or PowerShell as an Administrator.
  3. Run the following command (replace PhysicalDrive1 with your USB drive's disk number):
qemu-system-x86_64.exe -m 2048 -drive file=\\.\PhysicalDrive1,format=raw

4. Safety and Troubleshooting

  • Preventing Data Corruption: Avoid writing files or modifying ISOs on the Ventoy partition while the virtual machine is actively accessing the drive.
  • Permission Denied (Linux): Accessing raw block devices requires root privileges. Always run the command with sudo, or add your user account to the disk group.
  • Blank Screen or Slow Performance: Ensure virtualization (VT-x or AMD-V) is enabled in your system's motherboard BIOS/UEFI so -enable-kvm functions properly.
