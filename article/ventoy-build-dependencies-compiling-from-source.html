Ventoy Build Dependencies: Compiling from Source

Ventoy is an open-source utility designed to create bootable USB drives directly from ISO, WIM, IMG, and VHD files without repeatedly formatting the disk. Building the Ventoy project from its source code requires a comprehensive set of build systems, filesystem utilities, development headers, and cross-compilation toolchains to compile the core binaries and multi-architecture bootloaders. This article details the complete list of system packages, toolchains, and runtime dependencies required to compile the Ventoy project successfully.

Core Build Tools and Compilers

The primary build process relies on standard GNU compilation tools and source management utilities:

  • Git: Required to clone the repository and retrieve submodules.
  • GCC and G++: The GNU Compiler Collection is required to compile native host utilities and native modules.
  • GNU Make: Used to execute the Makefiles across the various project components.
  • CMake: Needed for configuring certain internal libraries and sub-modules.
  • Autoconf and Automake: Necessary for configuring GRUB source trees and associated dependencies.
  • Patch: Used to apply custom Ventoy modifications directly to upstream source codes such as GRUB.
  • Bison and Flex: Required for parser generation during GRUB and secondary bootloader builds.
  • Python (3.x): Used for build automation scripts, packaging routines, and asset processing.

Filesystem and Archive Utilities

Ventoy manages and generates various file systems and disk images during compilation, requiring dedicated manipulation tools:

  • dosfstools (mkfs.vfat): Creates and formats FAT16/FAT32 boot partitions.
  • mtools: Enables the manipulation of MS-DOS/FAT filesystems without mounting.
  • xorriso: Builds and extracts ISO9660 filesystem images.
  • squashfs-tools (mksquashfs): Generates compressed SquashFS images for target environments.
  • tar, gzip, bzip2, xz: Standard archive utilities needed to unpack build-time assets and package distribution binaries.

Libraries and Header Files

Compiling the user interface and system-level daemons requires several C-runtime libraries and development headers:

  • glibc-devel and glibc-static: Provides C standard library headers and static libraries necessary for creating standalone, portable binary tools.
  • ncurses / libncurses-dev: Required for building terminal-based user interface components.
  • zlib / zlib-devel: Provides compression algorithms used within boot image generation.
  • libuuid-devel: Handles Universally Unique Identifier creation for disk partitions.

Cross-Compilation Toolchains

Because Ventoy creates boot environments supporting legacy BIOS (x86) and UEFI systems across diverse architectures (x86_64, IA32, ARM64, MIPS64EL, and LoongArch64), cross-compilers are mandatory if compiling the full boot chain from scratch:

  • i686-linux-gnu-gcc: For 32-bit x86 BIOS and UEFI binaries.
  • x86_64-linux-gnu-gcc: For standard 64-bit x86 UEFI binaries.
  • aarch64-linux-gnu-gcc: For 64-bit ARM UEFI components.
  • mips64el-linux-gnu-gcc: For 64-bit Little-Endian MIPS UEFI support.
  • loongarch64-linux-gnu-gcc: For LoongArch architecture compilation.

The Containerized Alternative (Docker)

Due to the complexity of configuring cross-compilation toolchains and specific glibc versions on modern Linux distributions, the Ventoy project officially maintains a pre-configured Docker image containing all prerequisites. If using Docker to build the project, the only host dependencies required are Docker Engine and the Git client.
