Ventoy Auto Install: Handling Windows Unattended Files

Ventoy's auto-installation plugin provides a mechanism to automate Windows installations by dynamically linking unattended answer files (autounattend.xml) to ISO images at boot time. This article explains how the plugin detects, maps, and injects unattended configuration files into the Windows Setup environment without modifying the original ISO image.

The Core Mechanism

Windows Setup natively searches the root directories of all removable drives, optical media, and specific local paths for an answer file named autounattend.xml. Traditionally, injecting this file requires modifying the ISO or placing the file on a separate USB flash drive.

Ventoy bypasses the need for image modification. When an ISO is selected, the Ventoy core checks for matching rules defined in its configuration. If a match is found, Ventoy constructs a virtual floppy or virtual disk in system memory containing the specified answer file and hooks the OS bootloader. When Windows PE (Preinstallation Environment) initializes, it reads the virtual drive, detects the autounattend.xml file, and executes the unattended sequence.

Configuration via ventoy.json

The plugin relies on a configuration file located at /ventoy/ventoy.json on the first partition of the Ventoy USB drive. The structure uses an auto_install object containing an array of mapping rules:

{
    "auto_install": [
        {
            "image": "/ISO/Windows_11.iso",
            "template": "/ventoy/script/win11_unattend.xml"
        },
        {
            "image": "/ISO/Win10_Pro.iso",
            "template": [
                "/ventoy/script/win10_pro.xml",
                "/ventoy/script/win10_home.xml"
            ]
        }
    ]
}
  • Image Matching: The image property points to the absolute path of the target Windows ISO relative to the partition root. Ventoy matches the selected ISO path against these entries.
  • Template Mapping: The template property specifies the path to the XML answer file.

Multiple Template Selection

If the template key defines an array of paths rather than a single string, Ventoy prompts the user with an interactive boot menu upon launching the ISO. This allows an administrator to choose between multiple automated profiles—such as a domain-joined setup, a standalone configuration, or standard interactive installation—using a single Windows ISO.

Dynamic Variable Substitution

Ventoy allows dynamic variable substitution within the XML template before passing it to the installer. Special placeholders written into the XML file are evaluated and replaced in memory by Ventoy at runtime:

  • VTOY_ISO_PATH: Expands to the full path of the loaded ISO.
  • VTOY_PART_UUID: Contains the partition UUID of the installation drive.

This feature enables answer files to reference external drivers, scripts, or assets stored on the Ventoy partition without hardcoding drive letters, which frequently shift during the Windows installation phases.

Loading and Execution Flow

  1. The user selects a Windows ISO from the Ventoy boot menu.
  2. Ventoy evaluates /ventoy/ventoy.json for an associated auto_install rule.
  3. If mapped, Ventoy reads the designated XML file into memory and evaluates any dynamic variables.
  4. Ventoy creates an emulated storage device containing the finalized XML renamed to autounattend.xml.
  5. The Windows Boot Manager (bootmgr) and Windows PE kernel load.
  6. The Windows Setup process queries available drives, identifies the virtual device containing autounattend.xml, and carries out disk partitioning, image application, and user creation unattended.
