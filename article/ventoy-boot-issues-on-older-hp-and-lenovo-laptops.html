Ventoy Boot Issues on Older HP and Lenovo Laptops

Many users encounter boot failures when using standard Ventoy USB drives on older HP and Lenovo laptops. This issue primarily stems from proprietary UEFI firmware limitations, particularly strict partition order requirements, aggressive Secure Boot implementations, and flawed handling of hybrid bootable media. Understanding these firmware quirks clarifies why the bootloader halts and how to configure Ventoy to bypass these hardware-specific restrictions.

The Partition Number Bug (The Primary Culprit)

Standard Ventoy installations partition a USB flash drive into two sections: Partition 1 (a large exFAT partition for storing ISO files) and Partition 2 (a small, hidden FAT partition containing the VTOYEFI bootloader).

Older UEFI implementations on HP and Lenovo systems—specifically those manufactured between 2011 and 2016—contain non-compliant UEFI code. Instead of scanning all partitions for an EFI System Partition (ESP), their firmware looks strictly at Partition 1 for the \EFI\BOOT\BOOTX64.EFI bootloader. Because Ventoy places the boot files on Partition 2 to protect them from Windows drive-formatting errors, these laptops completely ignore the bootloader and report an error such as "Boot Device Not Found" or bypass the drive entirely.

Secure Boot and Shim Incompatibilities

Older Lenovo ThinkPads and HP Pavilion/ProBook models often have outdated Secure Boot certificate databases (db and dbx) embedded in their BIOS. Ventoy relies on the Linux Foundation shim bootloader to facilitate Secure Boot compliance.

When booted on older machines, the outdated firmware may fail to parse the modern MokManager keys or simply drop into an infinite reboot loop upon encountering standard Ventoy signatures. In some HP models, the firmware silently blocks execution without displaying a prompt to enroll the key, leading to a black screen or an immediate jump to the next boot device.

GPT vs. MBR Firmware Handling

Ventoy defaults to using the Master Boot Record (MBR) partition scheme to maximize compatibility between Legacy BIOS and modern UEFI. However, early 64-bit UEFI implementations in HP and Lenovo laptops often feature broken UEFI-MBR hybrid boot capabilities.

These laptops frequently fail to read UEFI boot entries from MBR-partitioned flash drives, expecting UEFI boots to be paired exclusively with a GUID Partition Table (GPT). Conversely, attempting to boot in CSM (Compatibility Support Module) or Legacy mode on these machines may stall if the BIOS fails to parse Ventoy’s modified boot sectors.

How to Resolve the Issue

To resolve these boot failures on affected HP and Lenovo hardware, apply the following adjustments:

  • Disable Secure Boot: Enter the BIOS/UEFI settings and turn off Secure Boot to prevent the machine from rejecting the Ventoy bootloader or halting on MokManager.
  • Switch to GPT Scheme: In the Ventoy installation tool, open the Option menu, select Partition Style, and set it to GPT before writing to the drive. This resolves detection failures on strict UEFI implementations.
  • Enable CSM/Legacy Boot: If the machine fails to boot in UEFI mode altogether, enable Legacy Support or CSM in the BIOS settings, boot via the standard USB legacy entry, and launch ISOs via Ventoy’s text-based legacy mode.
  • Update System BIOS: Check the manufacturer’s support portal for the latest BIOS update, as later revisions from HP and Lenovo often resolved early UEFI partition-scanning and key-enrollment bugs.
