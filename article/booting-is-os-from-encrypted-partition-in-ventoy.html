Booting ISOs from Encrypted Partition in Ventoy

Ventoy does not natively support booting ISO files stored directly inside an encrypted partition, such as those formatted with BitLocker, LUKS, or VeraCrypt. While Ventoy allows users to customize partitions and format the primary storage area with various standard filesystems, it cannot decrypt partitions at boot time to read and launch disk images. However, Ventoy does provide alternative built-in security features, such as menu and image-level password protection, to prevent unauthorized access.

Why Encrypted Partitions Are Not Supported

Ventoy works via a two-stage process: an EFI/BIOS bootloader stage (stored on a small hidden partition) and a runtime stage where the loaded operating system accesses the virtualized ISO on the main data partition.

Partition encryption prevents this process from functioning for two critical reasons:

  1. Bootloader Limitations: At power-on, Ventoy's GRUB-based boot environment must scan the storage partition to discover and list available ISO, WIM, and IMG files. Standard encryption layers (like Windows BitLocker or Linux LUKS) mask the file table and data blocks, rendering the partition unreadable to the bootloader without explicit, complex decryption drivers integrated into the firmware interface.
  2. Kernel Handover Failure: When an operating system boots from an ISO via Ventoy, Ventoy hooks the operating system's kernel to keep the ISO mounted as a virtual CD/DVD drive in RAM or disk. If the underlying physical partition is locked by encryption, the booted operating system cannot access the host ISO file during its hardware initialization phase, causing the boot process to crash or fail.

What Happens If You Encrypt the Ventoy Data Partition

If you apply encryption software like BitLocker, VeraCrypt, or LUKS to the partition containing your ISO files:

  • Ventoy will still initialize its primary bootloader (stored on the secondary VTOYBOOT partition).
  • Upon loading the Ventoy interface, the screen will report that no ISO files were found, or it will fail with an error stating the filesystem cannot be recognized.
  • You will be unable to access any tools, live environments, or installers until the partition is decrypted and restored to a supported standard filesystem (such as exFAT, NTFS, ext4, FAT32, or XFS).

Supported Alternatives for Securing Ventoy

While full partition encryption is not supported for booting, you can secure your files and restrict access using Ventoy's native configuration framework:

  • Global Password Protection: By adding a ventoy.json configuration file inside a ventoy folder on the main partition, you can enforce a password before the main Ventoy boot menu appears.
  • Per-Image Password Protection: You can set individual passwords for specific sensitive ISO files, ensuring that only authorized users can launch particular tools or operating system installers.
  • Dual-Partition Strategy: You can shrink the main Ventoy data partition and create a separate, third partition on the drive dedicated exclusively to encrypted data (using BitLocker or VeraCrypt). While ISOs inside that third partition cannot be booted, the partition can safely store sensitive files accessible once an operating system is running.
