Replace Ventoy Secure Boot Keys with Custom Keys

Ventoy includes built-in Secure Boot support using a pre-signed shim and its own default certificate, which typically prompts users to enroll a key using MokManager upon first boot. If you manage your own Unified Extensible Firmware Interface (UEFI) Secure Boot environment with custom Platform Keys (PK), Key Exchange Keys (KEK), and Signature Database (db) keys, you can replace Ventoy's default keys with your own. This guide provides a straightforward method to re-sign Ventoy's bootloader binaries using your personal private keys, allowing seamless booting on systems where your custom keys are enrolled.

Prerequisites

Before proceeding, ensure you have:

  • A working Linux environment.
  • sbsigntool installed for signing EFI binaries (available via package managers like apt install sbsigntool or pacman -S sbsigntools).
  • Your custom Secure Boot private key (db.key or MOK.key) and the matching public certificate (db.crt or MOK.crt).
  • A USB drive with Ventoy already installed.

Step 1: Mount the Ventoy EFI System Partition

Ventoy partitions the USB drive into two sections: the main data partition where ISO files reside, and a hidden FAT partition containing the bootloaders.

  1. Insert your Ventoy USB drive into your system.
  2. Identify the EFI partition (typically labeled VTOYEFI, usually partition 2, such as /dev/sdb2): 
    lsblk -f
  3. Create a temporary mount point and mount the partition: 
    sudo mkdir -p /mnt/vtoyefi
sudo mount /dev/sdX2 /mnt/vtoyefi
    (Replace /dev/sdX2 with your actual Ventoy EFI partition).

Step 2: Locate the EFI Binaries

Navigate to the EFI directory on the mounted partition:

cd /mnt/vtoyefi/EFI/BOOT

Inside this directory, you will find several .efi files depending on the architectures supported (e.g., BOOTX64.EFI, grubx64.efi, BOOTIA32.EFI, BOOTAA64.EFI).

Ventoy uses a standard chainloader approach:

  • BOOTX64.EFI is typically the shim loader.
  • grubx64.efi is the GRUB bootloader that loads the Ventoy interface.

Step 3: Strip Existing Signatures (Optional)

While sbsign can append signatures, removing the existing default signature prevents binary bloat and potential validation conflicts:

sudo sbattach --remove BOOTX64.EFI
sudo sbattach --remove grubx64.efi

Step 4: Sign the Binaries with Your Private Key

Use sbsign to sign the Ventoy bootloader binaries using your custom key pair.

  1. Sign the shim loader: 
    sudo sbsign --key /path/to/custom.key --cert /path/to/custom.crt --output BOOTX64.EFI BOOTX64.EFI
  2. Sign the GRUB loader: 
    sudo sbsign --key /path/to/custom.key --cert /path/to/custom.crt --output grubx64.efi grubx64.efi
  3. Repeat the process for any alternative architectures (such as ARM64 or 32-bit x86) if you plan to use the drive on those systems.

(Note: If your custom keys are enrolled directly into your motherboard's UEFI db database rather than as a MOK, you can bypass the shim entirely by copying grubx64.efi over BOOTX64.EFI after signing it with your db key).

Step 5: Unmount and Test

  1. Leave the directory and unmount the partition: 
    cd ~
sudo umount /mnt/vtoyefi
  2. Reboot your target machine with Secure Boot enabled.
  3. Select your Ventoy USB drive from the UEFI boot menu.

The system will verify the binaries directly against the custom certificates enrolled in your UEFI firmware, booting straight into the Ventoy menu without prompting for key enrollment through MokManager.
