How Ventoy Matches Autoinstall Scripts to ISOs

Ventoy determines which autoinstall script to deploy with a specific ISO file by reading user-defined configurations stored in a central JSON file. Rather than attempting to guess the operating system or automatically parse ISO metadata dynamically, Ventoy relies entirely on its auto_install plugin rules configured within /ventoy/ventoy.json. By mapping script file paths to specific ISO image paths, parent directories, or wildcard patterns, Ventoy knows precisely which Kickstart, Preseed, XML, or answer file to inject during boot.

The Role of ventoy.json

Ventoy looks for a configuration file located at /ventoy/ventoy.json on the root of the first partition (the partition where ISO files reside). To enable unattended installations, you declare an auto_install array within this file.

Inside this array, entries link ISO paths directly to one or more template scripts. A typical configuration looks like this:

{
    "auto_install": [
        {
            "image": "/ISO/Windows/Win10_22H2.iso",
            "template": "/ventoy/script/win10_unattend.xml"
        },
        {
            "image": "/ISO/Linux/ubuntu-22.04-live-server-amd64.iso",
            "template": "/ventoy/script/ubuntu_user_data"
        }
    ]
}

Matching Criteria and Evaluation Rules

When you select an ISO to boot from the Ventoy menu, the bootloader evaluates the auto_install array sequentially from top to bottom. It compares the selected ISO’s location and name against the "image" parameter using the following criteria:

  • Exact File Path: If the "image" property contains a full path to an ISO (such as /ISO/Rocky-9.iso), Ventoy triggers the match only when that exact file is selected.
  • Directory Matching: If the "image" path ends with a directory (or specifies a folder), any ISO booted from that folder inherits the mapped script. For example, pointing to /ISO/CentOS/ will match any ISO stored inside that subfolder.
  • Pattern and Wildcard Matching: Ventoy supports wildcards (such as *) inside the "image" string. Specifying /ISO/Debian*.iso ensures any Debian release matching the pattern uses the designated template.
  • Order Precedence: Because Ventoy evaluates rules sequentially, more specific paths should be placed above broader directory or wildcard rules in the JSON array to prevent unwanted matches.

Handling Multiple Matches and User Choice

If an image matches an entry where "template" is defined as an array of multiple scripts rather than a single string, Ventoy presents an interactive menu at boot time. This allows the user to manually select which script to apply (e.g., choosing between a "Desktop Minimal" or "Server Standard" installation) before the ISO boots.

If an ISO does not match any entry in the auto_install plugin, Ventoy proceeds with a standard, manual installation with no scripts injected.

Injection at Boot

Once a match is confirmed, Ventoy virtualizes a secondary drive or injects the matched script directly into the runtime memory/initrd structure depending on the target OS (such as creating a virtual floppy for Windows autounattend.xml or passing boot parameters for Linux Kickstart/Preseed). The target installer then detects the script as if it were on a physical disk attached to the machine.
