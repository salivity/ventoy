How to Enable Ventoy Verbose Debugging Output

This guide explains how to enable verbose debugging output during a Ventoy boot sequence to troubleshoot failed image loads, hardware incompatibilities, and bootloader crashes. By default, Ventoy uses a graphical interface and suppresses low-level system logs during image execution. The following methods demonstrate how to disable graphical suppression, enable GRUB2 debug logging, and inspect the runtime environment directly from the boot interface.

Method 1: Boot Using Text Mode (Ctrl + R)

Ventoy's graphical theme often masks the underlying terminal output where kernel panics and chainloading errors appear.

  1. Power on your system and boot into the main Ventoy drive menu.
  2. Highlight the ISO, WIM, or VHD file you wish to boot.
  3. Press Ctrl + R on your keyboard.
  4. Select the standard boot option from the prompt.

Ventoy will process the image through standard text mode rather than graphical mode, allowing you to see GRUB commands, file system mounting attempts, and standard error streams in real time.

Method 2: Enable GRUB2 Verbose Debugging

Because Ventoy is built on a modified GRUB2 core, you can manually trigger GRUB's built-in debugging engine via the command line interface before launching an image.

  1. At the main Ventoy selection screen, press c to drop into the GRUB command-line shell.
  2. To enable full verbose output for all GRUB operations, type: 
    set debug=all
  3. If the volume of messages is too large and you only need disk and bootloader logs, restrict the scope to specific subsystems: 
    set debug=disk,vtoypath,linux
  4. Press Esc to return to the main Ventoy menu.
  5. Select and boot your target image. GRUB will now dump verbose execution tracing directly to the display.

Method 3: Use the GRUB2 Boot Mode (Ctrl + G)

Certain ISOs fail silently under Ventoy's default hook-based boot mechanism. You can force Ventoy to use GRUB2's native loopback parser, which naturally outputs detailed error information if a file structure is invalid.

  1. Highlight your desired image in the Ventoy menu.
  2. Press Ctrl + G to switch the loader to "Grub2 Mode."
  3. Observe the loading steps printed to the screen as Ventoy parses the internal GRUB configurations of the target image.

Method 4: Access System and Hardware Diagnostics (F5 Tools)

To troubleshoot hardware detection issues such as missing storage drives or unsupported UEFI configurations:

  1. In the main Ventoy interface, press F5 to access the Tools menu.
  2. Select Check Ventoy Environment or hardware inspection items to verify that the USB drive geometry, partition types, and UEFI/Legacy flags are recognized properly.
  3. Review the reported variables before attempting to boot images that fail to detect underlying storage devices.
