How to Configure Ventoy Control in ventoy.json

The control section in ventoy.json serves as the central configuration block for defining global settings across a Ventoy bootable USB drive. By modifying this section, users can override default behaviors, customize boot menu interactions, set default search directories, adjust countdown timers, and toggle system compatibility workarounds. This guide explains how the control structure operates, outlines its key parameters, and demonstrates how to apply global rules to your Ventoy environment effectively.

The Purpose of the Control Section

Ventoy creates a plug-and-play boot environment by reading ISO, WIM, IMG, and VHD files directly from a USB storage partition. By default, Ventoy uses hardcoded parameters to locate files and render menus. Placing a ventoy.json file inside a /ventoy/ directory on the drive's first partition allows the system to read custom preferences.

Within this JSON file, the control key accepts an array or object containing directives that dictate how Ventoy scans the drive, displays the user interface, and handles operating system requirements.

Key Global Parameters in the Control Section

The control section uses specific key-value pairs to enforce global policies:

  • VTOY_DEFAULT_SEARCH_ROOT: Defines the specific folder Ventoy should search for bootable image files. Setting this prevents Ventoy from scanning the entire disk, speeding up the boot process.
  • VTOY_DEFAULT_IMAGE: Specifies the path of the default ISO or image file to boot if no user input is detected.
  • VTOY_MENU_TIMEOUT: Sets the countdown duration (in seconds) before the menu automatically selects the default boot image. Setting this to 0 halts the timer.
  • VTOY_SECONDARY_BOOT_MENU: Controls whether to display the secondary boot option menu when an ISO is selected (1 to enable, 0 to boot directly).
  • VTOY_FILT_DOT_UNDERSCORE: Filters out macOS metadata files (files starting with ._) from appearing as bootable options when images are copied via macOS.
  • VTOY_SORT_CASE_SENSITIVE: Determines whether image lists are sorted with case sensitivity (1 for enabled, 0 for disabled).
  • VTOY_WIN11_BYPASS_CHECK: Automatically bypasses Windows 11 installation checks (such as TPM 2.0, Secure Boot, and minimum RAM requirements) when launching Windows 11 ISOs.
  • VTOY_WIN11_BYPASS_NRO: Bypasses the mandatory online Microsoft Account requirement during Windows 11 setup.

Example Configuration

Below is a standard ventoy.json demonstrating how to structure the control block:

{
    "control": [
        { "VTOY_DEFAULT_SEARCH_ROOT": "/ISOs" },
        { "VTOY_MENU_TIMEOUT": "10" },
        { "VTOY_DEFAULT_IMAGE": "/ISOs/ubuntu-22.04.iso" },
        { "VTOY_SECONDARY_BOOT_MENU": "1" },
        { "VTOY_FILT_DOT_UNDERSCORE": "1" },
        { "VTOY_WIN11_BYPASS_CHECK": "1" },
        { "VTOY_WIN11_BYPASS_NRO": "1" }
    ]
}

Ventoy also accepts the control property as a direct object instead of an array:

{
    "control": {
        "VTOY_DEFAULT_SEARCH_ROOT": "/ISOs",
        "VTOY_MENU_TIMEOUT": "10",
        "VTOY_WIN11_BYPASS_CHECK": "1"
    }
}

Implementation Rules and Best Practices

  1. File Placement: The file must be named strictly ventoy.json (lowercase) and placed inside a folder named ventoy (lowercase) on the first partition of the USB drive (e.g., X:/ventoy/ventoy.json).
  2. JSON Syntax Validity: Strict JSON syntax must be followed. Trailing commas after the final key-value pair will cause parsing errors, forcing Ventoy to revert to default settings.
  3. Values as Strings: Most numerical toggles (such as "1" or "0") and timeouts should be enclosed in quotes to ensure compatibility across all Ventoy core versions.
