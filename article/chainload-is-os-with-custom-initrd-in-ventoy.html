Chainload ISOs with Custom Initrd in Ventoy

This guide explains how to bypass standard automated ISO boot routines in Ventoy to chainload an ISO file using customized initrd and kernel parameters. By configuring Ventoy’s secondary boot configuration file or leveraging Ventoy's native injection plugins, you can specify custom ramdisks, append initialization scripts, and override default kernel command-line arguments directly at boot time.

Method 1: Using ventoy_grub.cfg for Manual GRUB Loopback Booting

Ventoy automatically loads /ventoy/ventoy_grub.cfg from the first partition (the data partition) if the file exists. This method grants full control over the GRUB2 loopback mechanism, allowing you to load an ISO and pass multiple or modified initrd files.

1. Create the Configuration File

On your Ventoy USB partition, create a directory named ventoy (if it does not already exist) and place a file named ventoy_grub.cfg inside it:

/ventoy/ventoy_grub.cfg

2. Define the Menu Entry

Open ventoy_grub.cfg in a text editor and define a custom GRUB menu entry:

menuentry "Custom ISO Boot with Custom Initrd" --class custom {
    # Set the path to the ISO and custom initrd on the Ventoy partition
    set isofile="/ISOs/ubuntu-22.04-live-server-amd64.iso"
    set custom_initrd="/ISOs/custom_patch.cpio"

    # Search for the partition containing the ISO
    search --no-floppy --set=root --file $isofile

    # Mount the ISO to a loopback device
    loopback loop $isofile

    # Load the kernel from the loopback device with custom parameters
    linux (loop)/casper/vmlinuz boot=casper iso-scan/filename=$isofile quiet splash custom_arg=true ---

    # Chain multiple initrd files (the ISO's native initrd + your customized initrd)
    initrd (loop)/casper/initrd $custom_initrd
}

3. Booting via Ventoy

  1. Insert the USB drive and boot your machine.
  2. In the main Ventoy interface, press F6 to open the custom GRUB menu.
  3. Select your custom entry to boot using your specific kernel and initrd configuration.

Method 2: Using the Ventoy Injection Plugin

If you need to use Ventoy’s built-in ISO parser but require an additional or modified initrd archive (such as driver injections, kickstart scripts, or custom pre-mount binaries), use the native Injection Plugin. Ventoy merges the injected archive into the primary initrd in memory before booting.

1. Prepare the Override Archive

Create a gzipped or plain cpio archive containing your custom files. For example, to inject a script into the root filesystem:

mkdir -p /tmp/patch/etc
touch /tmp/patch/etc/custom_config
cd /tmp/patch
find . | cpio -o -H newc | gzip -9 > /path/to/ventoy/custom_initrd.cpio.gz

2. Configure ventoy.json

Create or edit /ventoy/ventoy.json on the first partition of the USB drive:

{
    "injection": [
        {
            "image": "/ISOs/ubuntu-22.04-live-server-amd64.iso",
            "archive": "/ventoy/custom_initrd.cpio.gz"
        }
    ]
}

3. Booting

Select and launch the ISO from the standard Ventoy menu. Ventoy intercepts the boot process, mounts the original ramdisk, merges the specified .cpio archive into memory, and launches the system with the modifications active.

Method 3: Replacing Boot Configuration with boot_conf_replace

If the objective is to edit existing boot arguments inside the ISO’s bootloader (such as changing the initrd path inside the ISO's internal grub.cfg or isolinux.cfg), use the Boot Conf Replace plugin.

  1. Extract the internal configuration file from the ISO (e.g., /boot/grub/grub.cfg).
  2. Modify the initrd and kernel parameters inside that file to suit your needs.
  3. Save the modified file on the Ventoy partition (e.g., /ventoy/custom_grub.cfg).
  4. Map the replacement in /ventoy/ventoy.json:
{
    "boot_conf_replace": [
        {
            "image": "/ISOs/custom_os.iso",
            "org.cfg": "/boot/grub/grub.cfg",
            "new.cfg": "/ventoy/custom_grub.cfg"
        }
    ]
}

When Ventoy loads the ISO, it automatically substitutes the original configuration file in memory with your modified version, preserving native hardware initialization while executing your custom startup parameters.
