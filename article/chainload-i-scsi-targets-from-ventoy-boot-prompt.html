Chainload iSCSI Targets From Ventoy Boot Prompt

Ventoy cannot natively chainload network-based iSCSI targets directly from its built-in boot prompt due to the absence of an integrated network stack and iSCSI initiator. While Ventoy excels at booting local ISO, IMG, VHD, and WIM files from USB drives, connecting directly to a Storage Area Network (SAN) target over IP requires specialized network boot protocols. This article covers why direct iSCSI chainloading is unsupported in standard Ventoy environments and outlines the standard workaround using an iPXE intermediate payload.

The Technical Limitation of Ventoy

Ventoy relies on a customized implementation of GRUB2 tailored specifically for local storage discovery and loopback image mapping. In a typical Ventoy installation, network drivers are not initialized, and the runtime environment does not include a TCP/IP network stack or an iSCSI initiator client.

Because the Ventoy boot prompt operates purely within this constrained local-boot environment, it lacks commands to configure network interfaces (such as obtaining an IP address via DHCP), authenticate with an iSCSI Qualified Name (IQN), or map an iSCSI Logical Unit Number (LUN) as a readable block device. Consequently, attempting to invoke an iSCSI URI directly from Ventoy's GRUB command line fails.

Ventoy vs. Network Bootloaders

Tools designed for network booting, such as iPXE, include native hardware drivers for network interface cards (NICs) alongside software implementations of network storage protocols. An iPXE environment provides the native sanboot command, which handles the following:

  1. Initializing the physical network interface.
  2. Acquiring network configuration via DHCP.
  3. Establishing a TCP connection to the target portal (typically port 3260).
  4. Performing the iSCSI login phase and mounting the remote target as an INT 13h (BIOS) or Block I/O (UEFI) device.

Ventoy's architecture delegates this functionality rather than duplicating it.

The Solution: Chainloading iPXE Through Ventoy

To boot an iSCSI target using a Ventoy drive, you must use an intermediary network bootloader capable of iSCSI initialization. The recommended approach is chainloading an iPXE binary stored on the Ventoy USB drive:

  1. Obtain an iPXE Binary: Download a pre-compiled iPXE executable appropriate for your system architecture (e.g., ipxe.efi for UEFI or ipxe.lkrn / ipxe.iso for legacy BIOS).
  2. Place the File on the Ventoy Drive: Copy the iPXE file directly into the standard file partition on the Ventoy USB drive.
  3. Boot into iPXE: Start the system, select the Ventoy device, and choose the iPXE image from the Ventoy menu.
  4. Initiate iSCSI Boot from iPXE: Once the iPXE shell loads, initialize the network and attach the target: 
    dhcp
sanboot iscsi:192.168.1.100::::iqn.2023-01.com.example:target-name

Using iPXE as a payload allows Ventoy to serve as the offline launching point while offloading the network-based storage attachment to a tool designed specifically for that purpose.
