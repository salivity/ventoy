iVentoy PXE Booting Without USB Drives

iVentoy revolutionizes network deployment by functioning as an enhanced PXE (Preboot Execution Environment) server that allows client machines to boot directly from ISO images stored on a central server. By bundling essential network services, serving raw ISO files without extraction, and virtualizing access to media over the local network, iVentoy completely removes the requirement for client-side physical USB drives or media flashing.

The PXE Handshake and Network Initialization

Client computers initiate the process through standard PXE capabilities built into their network interface cards (NICs). When a client system powers on with network boot selected in BIOS or UEFI:

  1. DHCP Request: The client broadcasts a request for network configuration.
  2. Network Offer: iVentoy provides an IP address (either via its internal DHCP server or by proxying alongside an existing router DHCP server) along with the next-server IP and bootloader filename.
  3. TFTP Stage: The client downloads an initial, lightweight network bootloader (iPXE) via Trivial File Transfer Protocol (TFTP).
  4. HTTP Transition: Once the iPXE environment initializes, iVentoy switches communication to high-speed HTTP, which drastically improves data transfer speeds compared to standard TFTP.

Direct ISO Reading Without Extraction

Traditional network boot configurations require system administrators to extract operating system ISOs, configure specific kernel parameters, and build custom boot scripts for every individual distribution. iVentoy bypasses this entirely:

  • Central Storage Repository: Administrators drop standard, unmodified ISO files into iVentoy's designated iso directory.
  • Dynamic Menu Generation: When the client connects, iVentoy scans the directory and presents an interactive boot menu listing all available operating systems.
  • Direct Streaming: The client selects an image, and iVentoy streams the necessary boot sectors and runtime files directly from the ISO file over the local network.

Runtime Virtual Drive Emulation

The primary obstacle to booting an installer without a physical drive is that operating system installers expect a local storage device (like a DVD drive or USB flash drive) once the kernel loads.

iVentoy solves this through runtime memory hooks and virtual drive emulation:

  • Bootloader Hooking: iVentoy intercepts the initial OS boot sequence and injects a custom driver into the loading environment.
  • Virtual Media Presentation: This driver connects back to the iVentoy server over the network and emulates a local CD/DVD-ROM or USB device inside the client's operating memory.
  • Installer Transparency: The operating system installer interacts with the virtual device as if it were a physical USB stick plugged directly into the machine, pulling installation packages across the network without failing due to missing installation media.

Cross-Architecture Firmware Compatibility

iVentoy handles diverse client hardware automatically. It detects whether a client connects via Legacy BIOS, 32-bit UEFI, 64-bit UEFI, or ARM64 UEFI. It dynamically serves the correct architecture-specific bootloader to the client without requiring manual reconfiguration or separate network shares, ensuring a seamless, plug-and-play network boot infrastructure.
