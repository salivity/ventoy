Where to Find Ventoy Bootloader Error Logs

Finding detailed error logs for the Ventoy bootloader depends on whether the issue occurred during the USB creation process or while booting an operating system. Because Ventoy operates in a pre-boot environment, it does not write persistent text logs to the USB drive during the boot phase by default. Instead, installation logs are saved directly to your host operating system, while bootloader runtime errors are displayed in memory, on-screen, or through the integrated command console.

1. Ventoy Installation and Setup Logs

If Ventoy fails to install, format, or update your USB drive, it creates a detailed log file automatically on the host operating system:

  • Windows: Look inside the extracted Ventoy folder containing Ventoy2Disk.exe. Ventoy writes a file named log.txt in this exact directory. If the operation fails, open this file with a text editor to view partition errors, disk access restrictions, or formatting failures.
  • Linux: When executing ./Ventoy2Disk.sh, logs are output directly to the terminal standard output. Ventoy also generates a log.txt file in the working directory from which the script was executed.

2. Boot-Time and Runtime Errors

Because the bootloader runs before an operating system is loaded, and because the EFI system partition is often protected or mounted read-only, runtime errors cannot be saved to a standard text file on the drive. To view runtime errors:

  • On-Screen Error Prompts: When an ISO fails to load, Ventoy halts execution and prints the exact error code (such as memory mapping failures, missing file signatures, or allocation errors) directly on the display. Take a photograph of this screen for troubleshooting.
  • GRUB Command Line: At the Ventoy boot menu, press c to drop into the underlying GRUB command-line interface. From here, you can manually inspect boot variables, test partition visibility with ls, and view terminal error messages generated when trying to mount virtual disks.
  • Ventoy Tools Menu: Press F5 while at the Ventoy main menu to open the internal Tools menu. From here, you can run hardware identification routines, resolution checks, and self-tests that print diagnostic information directly to the screen.

3. Enabling Verbose Boot Information

To make boot errors visible rather than letting them pass silently or cause an immediate reboot, customize the ventoy.json configuration file located in the ventoy folder on your storage partition:

  • Disable Silent Boot: Ensure your configuration does not hide boot messages by avoiding themes that suppress standard GRUB console output.
  • Text Mode: Switch the display to text mode via F5 -> Theme Select -> Text Mode to prevent high-resolution graphical display drivers from masking kernel or bootloader crash logs during initial image execution.
