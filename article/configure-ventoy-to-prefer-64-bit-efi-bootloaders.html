Configure Ventoy to Prefer 64-Bit EFI Bootloaders

This guide explains how to force or configure Ventoy to prioritize 64-bit (x86_64) EFI bootloaders over 32-bit (IA32) implementations. On hardware platforms with mixed or dual-architecture UEFI firmware—such as certain Intel Atom tablets and budget laptops—the system firmware may default to 32-bit EFI execution. By modifying the boot files within Ventoy's dedicated EFI system partition or adjusting firmware boot parameters, you can ensure that the 64-bit EFI environment is always loaded first.

Understanding Ventoy's EFI Architecture

Ventoy formats storage drives into two partitions:

  1. Partition 1 (Ventoy): An exFAT, NTFS, or ext4 partition that holds your ISO, WIM, and IMG files.
  2. Partition 2 (VTOYEFI): A small, hidden FAT partition containing the bootloaders for different hardware architectures (BOOTX64.EFI for 64-bit x86, BOOTIA32.EFI for 32-bit x86, BOOTAA64.EFI for ARM64, and BOOTMIPS64EL.EFI for MIPS).

Because UEFI firmware loads the bootloader prior to launching Ventoy's main interface, Ventoy cannot dynamically override the architecture chosen by the motherboard firmware. To prioritize or force 64-bit EFI, you must modify the boot binaries on the VTOYEFI partition or select the proper boot path in your motherboard setup.

Method 1: Disable 32-Bit EFI on the Ventoy EFI Partition

The most reliable way to force 64-bit execution is to disable or remove the 32-bit EFI binary from Ventoy’s hidden system partition. This forces the host firmware to bypass the 32-bit entry and execute BOOTX64.EFI.

On Windows:

  1. Insert the Ventoy USB drive.
  2. Open Command Prompt or PowerShell as Administrator.
  3. Launch the DiskPart utility: 
    diskpart
  4. List the disks and select your Ventoy drive: 
    list disk
select disk X
    (Replace X with your USB drive number.)
  5. List partitions and select the VTOYEFI partition (typically Partition 2, ~32MB in size): 
    list partition
select partition 2
  6. Assign a temporary drive letter to access the files: 
    assign letter=Z
exit
  7. Open File Explorer or use the command line to navigate to Z:\EFI\BOOT\.
  8. Locate BOOTIA32.EFI and rename it to BOOTIA32.EFI.bak (or delete it entirely).
  9. Remove the drive letter via DiskPart: 
    diskpart
select disk X
select partition 2
remove letter=Z
exit

On Linux:

  1. Insert the Ventoy USB drive.
  2. Identify the second partition using lsblk (e.g., /dev/sdb2).
  3. Mount the partition to a temporary directory: 
    sudo mkdir -p /mnt/vtoyefi
sudo mount /dev/sdb2 /mnt/vtoyefi
  4. Navigate to the bootloader directory: 
    cd /mnt/vtoyefi/EFI/BOOT/
  5. Rename the 32-bit binary: 
    sudo mv BOOTIA32.EFI BOOTIA32.EFI.bak
  6. Unmount the partition: 
    cd ~
sudo umount /mnt/vtoyefi

Method 2: Selecting 64-Bit EFI via Motherboard Boot Override

If your device supports both 32-bit and 64-bit UEFI environments, the firmware boot menu may present separate options for each:

  1. Connect the Ventoy drive to the target computer.
  2. Power on the system and press the boot menu key (typically F8, F11, F12, or Esc).
  3. Look for explicit architecture tags in the boot list, such as:
    • UEFI: <Device Name>, Partition 2 (x64)
    • UEFI: <Device Name> (64-bit)
  4. If your UEFI setup has a file browser boot override (common on modern AMI and Insyde BIOSes), select Boot from File, navigate to EFI -> BOOT -> BOOTX64.EFI, and press Enter.

Method 3: Handling Dual-Architecture ISOs with ventoy.json

Once the 64-bit EFI loader is running, certain multi-architecture ISOs (such as dual-architecture Windows or Linux installers) may default to a specific architecture.

To configure how Ventoy interacts with files on Partition 1:

  1. Open the primary Ventoy partition (where your ISOs are stored).
  2. Create a folder named ventoy if it does not already exist.
  3. Create or edit ventoy.json inside that folder.
  4. Use standard Ventoy controls to manage the boot menu presentation and file ordering. For multi-architecture images, Ventoy will automatically inherit the bitness of the EFI environment loaded at startup (x86_64 once BOOTIA32.EFI is disabled).
