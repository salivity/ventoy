Ventoy Mass Deployment Script for Enterprise

This article provides a comprehensive guide on automating the deployment of Ventoy across multiple USB drives in an enterprise environment. By leveraging Ventoy's native command-line interface (CLI) utilities on Linux and Windows, administrators can eliminate manual formatting, guarantee consistent partition structures, and automatically inject custom configurations and image files. The following sections walk through target detection, non-interactive execution commands, post-installation payload automation, and a production-ready Bash script.

Understanding Ventoy Command-Line Utilities

Ventoy includes command-line tools designed for unattended operations: Ventoy2Disk.sh for Linux and Ventoy2Disk.exe (in CLI mode) for Windows. In an enterprise deployment pipeline, these utilities allow administrators to bypass graphical user interface (GUI) prompts and format drives programmatically.

Key flags for Ventoy2Disk.sh include:

  • -i or -I: Installs Ventoy to the target disk. The uppercase -I forces the installation without interactive confirmation.
  • -u: Non-destructively upgrades an existing Ventoy installation.
  • -s: Enables Secure Boot support (recommended for modern enterprise fleets).
  • -g: Uses GPT partition style instead of MBR (essential for modern UEFI-only hardware).
  • -r <size_mb>: Reserves empty space at the end of the disk for secondary partitions or localized data.

Identifying Target Storage Devices Safely

The primary risk in automated USB imaging is accidentally overwriting internal system disks. A robust deployment script must validate device types (ensuring the transport bus is usb) before invoking the installation binary.

On Linux, lsblk can filter devices by transport type:

TARGET_DISKS=$(lsblk -d -n -o NAME,TRAN | awk '$2=="usb" {print "/dev/"$1}')

On Windows, PowerShell provides similar functionality via CIM/WMI:

$TargetDrives = Get-Disk | Where-Object { $_.BusType -eq 'USB' -and $_.OperationalStatus -eq 'Online' }

Developing the Linux Deployment Script

The following Bash script identifies all currently connected USB mass-storage devices, verifies their capacity, executes an unattended GPT/Secure Boot installation of Ventoy, and mounts the primary partition to deploy global configuration files.

#!/usr/bin/env bash
set -euo pipefail

VENTOY_DIR="/opt/ventoy"
CONFIG_SOURCE="/srv/deployment/ventoy.json"
ISO_SOURCE_DIR="/srv/deployment/iso"

if [[ $EUID -ne 0 ]]; then
   echo "Error: This script must be run as root." >&2
   exit 1
fi

# Detect all connected USB block devices
mapfile -t USB_DEVICES < <(lsblk -dno NAME,TRAN | awk '$2=="usb" {print "/dev/"$1}')

if [[ ${#USB_DEVICES[@]} -eq 0 ]]; then
    echo "No USB devices detected."
    exit 0
fi

for DEV in "${USB_DEVICES[@]}"; do
    echo "Processing target device: ${DEV}"

    # Unmount any currently mounted partitions on the device
    umount "${DEV}"* 2>/dev/null || true

    # Execute non-interactive installation: Force (-I), Secure Boot (-s), GPT (-g)
    "${VENTOY_DIR}/Ventoy2Disk.sh" -I -s -g "${DEV}"

    # Wait for the kernel to register the new partition table
    sleep 3
    partprobe "${DEV}" || true

    # Ventoy partition 1 holds the data/ISOs
    DATA_PART="${DEV}1"

    # Create temporary mount point
    MOUNT_POINT=$(mktemp -d)
    mount "${DATA_PART}" "${MOUNT_POINT}"

    # Inject enterprise ventoy.json configuration
    mkdir -p "${MOUNT_POINT}/ventoy"
    if [[ -f "${CONFIG_SOURCE}" ]]; then
        cp "${CONFIG_SOURCE}" "${MOUNT_POINT}/ventoy/"
    fi

    # Sync pre-approved enterprise ISO files
    if [[ -d "${ISO_SOURCE_DIR}" ]]; then
        rsync -av --progress "${ISO_SOURCE_DIR}/" "${MOUNT_POINT}/"
    fi

    # Clean up
    sync
    umount "${MOUNT_POINT}"
    rmdir "${MOUNT_POINT}"

    echo "Successfully provisioned ${DEV}."
done

Automating Windows Deployment with PowerShell

For Windows management stations, Ventoy2Disk.exe supports the VTOYCLI mode for unattended installations.

The command syntax is:

Ventoy2Disk.exe VTOYCLI /I /Drive:X:

A production PowerShell script wraps this command:

$VentoyCli = "C:\Ventoy\Ventoy2Disk.exe"
$UsbDrives = Get-Disk | Where-Object { $_.BusType -eq 'USB' }

foreach ($Disk in $UsbDrives) {
    # Get associated drive letter if mounted
    $Partition = Get-Partition -DiskNumber $Disk.Number | Where-Object DriveLetter | Select-Object -First 1
    
    if ($Partition) {
        $DriveLetter = "$($Partition.DriveLetter):"
        Write-Host "Installing Ventoy on $DriveLetter (Disk $($Disk.Number))..."
        
        # /I = Install, /EnSecureBoot = Secure Boot support, /GPT = GPT scheme
        Start-Process -FilePath $VentoyCli -ArgumentList "VTOYCLI /I /GPT /EnSecureBoot /Drive:$DriveLetter" -Wait -NoNewWindow
    }
}

Enterprise Configuration Management: ventoy.json

An essential part of mass deployment is pre-configuring standard organizational policies. The primary data partition should automatically receive a /ventoy/ventoy.json file during the post-installation phase.

This JSON file standardizes the user environment across all deployed media:

{
  "control": [
    { "VTOY_DEFAULT_SEARCH_ROOT": "/ISOs" },
    { "VTOY_MENU_TIMEOUT": 10 },
    { "VTOY_DEFAULT_IMAGE": "/ISOs/Enterprise_Win11_x64.iso" }
  ],
  "theme": {
    "file": "/ventoy/theme/enterprise_theme.txt",
    "display_mode": "GUI"
  }
}

By coupling automated partitioning scripts with centralized configuration templates, enterprise system administrators can rapidly stage standardized, policy-compliant, bootable media across thousands of client drives with minimal human intervention.
