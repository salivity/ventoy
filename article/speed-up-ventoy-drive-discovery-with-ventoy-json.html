Speed Up Ventoy Drive Discovery with ventoy.json

Ventoy scans connected storage partitions at boot to identify bootable image files, which can cause noticeable delays on large capacity or fragmented drives. This guide covers the specific configuration flags available in ventoy.json that optimize initial drive discovery by narrowing directory scopes, reducing recursive search depths, and bypassing unnecessary disk reads during the boot sequence.

Target Specific Directories with search_path

By default, Ventoy traverses every folder on the partition to locate compatible image files. On drives with thousands of files or complex directory trees, this full-drive discovery drastically increases startup time.

You can restrict Ventoy to scan only designated folders using the search_path property.

{
    "ventoy": {
        "search_path": ["/ISO", "/Images"]
    }
}

Defining one or more explicit paths stops Ventoy from examining the root directory and non-bootable storage locations, resulting in an immediate reduction in discovery time.

Limit Directory Traversal with max_search_level

Even when using designated directories, recursive directory checking can slow down menu initialization. The max_search_level parameter sets the maximum directory depth Ventoy will traverse from the base search location.

The default value is 0 (or unset), which scans indefinitely deep. Reducing this value prevents deep recursion:

{
    "ventoy": {
        "max_search_level": 1
    }
}

Setting max_search_level to 1 instructs Ventoy to scan only the immediate folder specified and ignore deeper subdirectories, significantly speeding up file enumeration.

Example Optimized ventoy.json

To apply these optimizations, create or edit the ventoy.json file inside the ventoy directory on your USB drive's primary data partition (/ventoy/ventoy.json).

{
    "ventoy": {
        "search_path": ["/boot_images"],
        "max_search_level": 1
    }
}

With this configuration, Ventoy bypasses the global disk scan and only evaluates files residing directly inside /boot_images, resulting in near-instantaneous drive discovery and boot menu generation.
