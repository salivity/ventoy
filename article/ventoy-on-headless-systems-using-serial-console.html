Ventoy on Headless Systems Using Serial Console

Ventoy can run on headless systems using serial console redirection, allowing administrators to deploy operating systems on servers and embedded devices without a monitor or keyboard. Because Ventoy is built on a customized GRUB2 core, it inherits GRUB's native support for serial communication. By forcing Ventoy into text mode and defining serial terminal parameters through custom configuration files, you can redirect the bootloader menu and interaction over a physical serial port or virtual serial console.

How Serial Redirection Works in Ventoy

By default, Ventoy boots into a graphical user interface (GUI) optimized for standard video output (HDMI, DisplayPort, or VGA). Serial interfaces cannot display this graphical menu. To make Ventoy functional over a serial connection:

  1. Ventoy must switch from its default GUI theme to a text-based interface.
  2. The underlying GRUB subsystem must initialize the serial hardware (UART/COM port) with the correct baud rate, data bits, parity, and stop bits.
  3. Input and output streams must be mapped to both the serial console and standard console (dual output) to ensure access is maintained across different interfaces.

Configuring Ventoy for Serial Console

Serial console redirection in Ventoy is configured using two configuration files stored in the ventoy directory on the USB drive's primary data partition.

Step 1: Force Text Mode via ventoy.json

Create or edit ventoy/ventoy.json to disable the graphical theme, which ensures the menu can render via text-only terminals:

{
  "theme": {
    "display_mode": "text"
  }
}

Setting display_mode to text prevents Ventoy from attempting to load graphics drivers that fail or hang on headless hardware.

Step 2: Inject Serial Commands via ventoy_grub.cfg

Ventoy allows custom GRUB script execution before the main menu loads through a file named ventoy/ventoy_grub.cfg. Create this file to initialize the serial port and redirect GRUB's input/output:

# Initialize the first serial port (ttyS0 / COM1) at 115200 baud
serial --unit=0 --speed=115200 --word=8 --parity=no --stop=1

# Route terminal input and output to both console and serial
terminal_input --append serial
terminal_output --append serial
  • --unit=0 targets COM1 / ttyS0. Change this to --unit=1 for COM2 / ttyS1, depending on your server's serial port or IPMI Serial-over-LAN (SoL) configuration.
  • --append allows the bootloader to listen on both the local screen/keyboard (if present) and the serial line simultaneously.

Booting Target Operating Systems

Redirecting Ventoy's menu does not automatically redirect the operating system you select. Once an ISO or image is selected from the Ventoy menu:

  • Linux Installers: You must edit the kernel command-line arguments at boot (usually by pressing e or Tab in the target OS bootloader) to append serial flags, such as console=tty0 console=ttyS0,115200n8.
  • Windows PE / Windows Server: The boot image must have EMS (Emergency Management Services) enabled or be configured via boot.ini / BCD to route installer output to the COM port.
  • BSD Systems: Append serial loader flags (e.g., -h or setting boot_multicons="YES") to maintain redirection after the kernel initializes.
