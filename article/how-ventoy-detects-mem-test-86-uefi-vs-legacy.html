How Ventoy Detects MemTest86 UEFI vs Legacy

This article explains how the multiboot tool Ventoy distinguishes between UEFI and Legacy BIOS versions of MemTest86. Because PassMark MemTest86 transitioned from a Legacy-only architecture (version 4.x and earlier) to a strictly UEFI-based architecture (version 5.0 and later), Ventoy must dynamically inspect both the current host firmware state and the internal boot structures of the image file to properly launch the memory diagnostic tool.

Firmware Environment Detection

Ventoy operates using a customized GRUB2 core that detects the host machine's active boot mode upon initialization. If the physical machine boots Ventoy in Legacy BIOS mode, Ventoy operates entirely within an x86 real-mode/protected-mode context. If booted under modern hardware with UEFI enabled, Ventoy runs as a native EFI application. This initial check establishes which execution paths are physically possible on the system; Legacy payloads cannot be executed directly from a UEFI session without a Compatibility Support Module (CSM), and UEFI applications cannot run under a Legacy BIOS.

Image Structure Analysis

When an administrator places a MemTest86 image (typically distributed as a .iso or raw .img file) on the Ventoy storage partition, Ventoy inspects the image contents rather than relying solely on file extensions:

  1. UEFI MemTest86 Images (v5+): Modern versions use a GPT or hybrid partition layout containing a FAT-formatted EFI System Partition (ESP). Ventoy checks for the existence of standard UEFI execution binaries, specifically paths such as /EFI/BOOT/BOOTX64.EFI or /EFI/BOOT/BOOTIA32.EFI.
  2. Legacy MemTest86 Images (v4.x and Memtest86+): Older images rely on an MBR boot sector or an El Torito boot record without an EFI directory. Ventoy scans the boot sector signatures and identifies the presence of 16-bit real-mode or 32-bit protected-mode bootstrap code designed to hook BIOS interrupts (such as INT 13h).

Boot Execution Routing

Once the format is recognized and compared against the current host environment, Ventoy routes the execution path accordingly:

  • In UEFI Mode: If a modern MemTest86 image is selected, Ventoy's virtual disk driver maps the image in system memory and directly chainloads the internal .efi application using UEFI standard boot services. If a Legacy-only MemTest86 image is selected while running in UEFI mode, Ventoy identifies the lack of an EFI bootloader and warns the user that the image is incompatible with the current UEFI environment.
  • In Legacy Mode: When launching Legacy-compatible MemTest86, Ventoy utilizes memory-mapping routines (similar to Memdisk emulation) to load the raw sectors and pass control to the 16-bit MBR boot code. If a UEFI-only MemTest86 image is selected while running in Legacy mode, Ventoy detects the missing BIOS boot code and prompts the user to reboot the system into native UEFI mode to run the image.
