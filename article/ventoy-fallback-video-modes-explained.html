Ventoy Fallback Video Modes Explained

When Ventoy cannot initialize high-resolution graphics on a target machine, it relies on automated display fallbacks and alternative console modes to ensure the boot menu remains accessible. This article details the specific video mechanisms, lower-resolution steps, and text-based console modes Ventoy employs when native graphical drivers fail to load properly across both UEFI and Legacy BIOS environments.

The Standard Display Engine

Ventoy relies on GRUB2 as its core boot environment. Under normal conditions, Ventoy queries the firmware to determine the monitor's native panel resolution:

  • UEFI Mode: Uses the UEFI Graphics Output Protocol (GOP).
  • Legacy BIOS Mode: Uses VESA BIOS Extensions (VBE).

If the detected native resolution cannot be rendered due to memory constraints, corrupt EDID data, or buggy firmware implementations, Ventoy initiates its fallback process.

Safe Resolution Stepping

Before abandoning graphical mode altogether, Ventoy attempts to negotiate standard, universally supported display resolutions. If native panel rendering fails, the bootloader steps down through conservative standard VESA/GOP display modes:

  1. 1024x768 (32-bit/24-bit color): The primary safe graphical baseline for most modern x86 hardware.
  2. 800x600: The secondary safe mode used if the display controller rejects 1024x768.
  3. 640x480: The legacy standard baseline mode, ensuring maximum compatibility across older or virtualized environments.

During this process, the graphical theme or background may automatically scale down or be disabled to ensure graphical menus load without overflowing the video buffer.

Fallback to Text Mode (CLI)

If all graphical initialization routines fail, or if video memory cannot be mapped by the bootloader, Ventoy completely disengages the graphical rendering pipeline (terminal_output gfxterm) and falls back to text mode:

  • Legacy BIOS: Reverts to the standard IBM VGA 80x25 alphanumeric text mode (terminal_output console). In this state, the bootloader uses minimal hardware resources, bypassing video buffers entirely.
  • UEFI: Reverts to the UEFI Simple Text Output Protocol, which renders basic monospace characters directly through firmware console services without a GUI layer.

Manual Overrides and Configuration

Users encountering display initialization errors can manually force fallback behavior without waiting for an automated crash recovery:

  • F7 Hotkey: Pressing F7 on the main Ventoy screen toggles the interface directly between Graphical (GUI) mode and Text (CLI) mode.
  • Ventoy Configuration File: In ventoy.json, setting the display_mode parameter to "cli" forces Ventoy to bypass graphical mode on boot: 
    {
    "control": [
        { "display_mode": "cli" }
    ]
}
  • Resolution Locking: You can lock a safe fallback resolution manually by defining "ventoy_resolution": "1024x768" or "800x600" within the configuration file, preventing Ventoy from attempting unsupported native resolutions.
