How Ventoy Protects Itself From Installer Partitioning

When booting operating system installation media from a multiboot USB, automated or manual partitioning tools could potentially overwrite the live boot drive. Ventoy prevents installer partitioning utilities from wiping out its active session through a combination of kernel-level file locks, runtime initramfs hooks, and block device busyness states. By ensuring the host storage medium remains an active, unmountable dependency of the running installer environment, Ventoy renders the drive read-only to partitioning operations and signals to installer software that the disk must be excluded as a target destination.

The Problem with Live USB Partitioning

Traditional single-ISO USB drives behave as read-only optical discs (using hybrid ISO9660 formats), which many installers recognize directly. Multiboot tools like Ventoy, however, store raw ISO files on a writable, standard partition (typically exFAT, NTFS, or ext4). When an OS installer initializes, its storage manager scans all connected block devices. Without specific protections, a user or an automated script might select the Ventoy USB drive as the installation target, wiping the partition table while the system is actively running from it.

Active Loopback Mounting and the "Device Busy" State

Ventoy's primary defense on Linux-based installers relies on the operating system kernel's native device locking mechanisms.

  1. Initramfs Hooking: During boot, Ventoy intercepts the boot process by injecting a custom hook into the target ISO's initial RAM disk (initramfs).
  2. Mounting the Source Partition: Ventoy locates the host USB drive and mounts the partition containing the target ISO file.
  3. Loop Device Creation: Ventoy maps the ISO file to a virtual loop block device (/dev/loopX) or uses a device-mapper snapshot, which the installer then mounts as its root filesystem (/).

Because the active root filesystem depends entirely on the loop device, and the loop device holds an open file descriptor on the underlying USB partition, the Linux kernel marks both the partition and the parent block device as busy (EBUSY).

Standard partitioning utilities—such as parted, gparted, fdisk, and wipefs—query the kernel before altering partition tables. When an application attempts to write a new partition scheme to a disk with active, mounted partitions, the kernel denies write access to the partition table. Any command attempting to unmount the Ventoy partition fails because the operating system's active runtime binaries reside within it.

Automatic Installer Medium Exclusion

Modern installation frameworks—including Anaconda (Fedora/RHEL), Calamares (used by many distributions), Subiquity/Ubiquity (Ubuntu), and Debian-Installer—specifically inspect the system's mount points prior to listing available destination disks.

These tools parse files like /proc/mounts, /proc/swaps, and lsblk trees to identify the storage medium hosting /cdrom, /rofs, or the root filesystem. Upon identifying the parent block device of the active installation repository, the installer automatically filters that entire disk out of the target disk selection UI to prevent self-destruction.

Windows Setup and Virtual Drive Emulation

For Windows operating systems, the mechanism functions differently due to how Windows Setup handles block storage. Ventoy injects a lightweight driver into the Windows Preinstallation Environment (WinPE) memory space during the initial boot phase.

This driver creates a virtual CD-ROM drive in memory that exposes the ISO contents directly to Windows Setup. Windows Setup detects the physical USB disk as the installation source drive holding boot critical data. Windows natively prevents users from formatting, repartitioning, or selecting the volume containing the active bootmgr and setup files during the drive selection phase of the installation wizard.

Dual-Partition Layout Isolation

Ventoy structures its drives using a two-partition scheme:

  • Partition 1: The larger, visible partition holding ISO files, plugins, and images.
  • Partition 2 (VTOYEFI): A small, protected FAT16 partition containing the GRUB bootloader, EFI binaries, and core Ventoy software.

Because all active boot files and the ISO container are distributed across these distinctly assigned partitions, the core boot loader remains physically separated from storage-level data manipulations performed within user-space operating system tools.
