Build a Pre-Seeded Ventoy Image Using Docker

Yes, you can create a custom, pre-seeded Ventoy disk image using Docker. By running the Ventoy installation scripts inside a Linux container, you can automate the generation of raw disk image (.img) files pre-configured with themes, configuration settings (ventoy.json), unattended installation scripts, and bootable ISOs. This guide covers the containerized workflow needed to build a deployable, headless Ventoy image ready for distribution or direct flashing to USB drives.

The Containerized Approach

Ventoy typically installs directly to physical block devices, but its command-line utilities also support raw disk image files. Using Docker allows you to isolate dependencies—such as parted, fdisk, and util-linux—and produce identical, portable .img artifacts across different development environments without risking your host machine's partition tables.

Requirements for the Docker Host

To manipulate virtual block devices and loop mounts, your Docker environment requires elevated permissions:

  • Docker engine installed on a Linux host.
  • Container runtime with privileged access (--privileged) to allow losetup and mount operations within the container.

Step 1: Create the Dockerfile

The Dockerfile installs the necessary partitioning utilities and downloads the official Ventoy release.

FROM ubuntu:22.04

ENV DEBIAN_FRONTEND=noninteractive
ENV VENTOY_VERSION=1.0.99

RUN apt-get update && apt-get install -y \
    wget \
    tar \
    parted \
    util-linux \
    dosfstools \
    udev \
    e2fsprogs \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /workspace

# Download and extract the Ventoy Linux distribution
RUN wget https://github.com/ventoy/Ventoy/releases/download/v${VENTOY_VERSION}/ventoy-${VENTOY_VERSION}-linux.tar.gz \
    && tar -xzf ventoy-${VENTOY_VERSION}-linux.tar.gz \
    && mv ventoy-${VENTOY_VERSION} ventoy \
    && rm ventoy-${VENTOY_VERSION}-linux.tar.gz

COPY build.sh /workspace/build.sh
RUN chmod +x /workspace/build.sh

ENTRYPOINT ["/workspace/build.sh"]

Step 2: Create the Image Creation Script (build.sh)

The build script creates a blank raw disk file, initializes Ventoy on it, and copies over your pre-seeded configurations.

#!/bin/bash
set -e

IMAGE_NAME="/output/ventoy_custom.img"
IMAGE_SIZE_MB=${IMAGE_SIZE_MB:-4096}

echo "1. Allocating blank image file (${IMAGE_SIZE_MB}MB)..."
dd if=/dev/zero of="${IMAGE_NAME}" bs=1M count="${IMAGE_SIZE_MB}" status=progress

echo "2. Installing Ventoy to disk image..."
cd /workspace/ventoy
# -I forces installation; -g specifies GPT partition scheme
sh Ventoy2Disk.sh -I -g "${IMAGE_NAME}"

echo "3. Attaching image via loop device..."
LOOP_DEV=$(losetup -fP --show "${IMAGE_NAME}")
DATA_PART="${LOOP_DEV}p1"

mkdir -p /mnt/ventoy
mount "${DATA_PART}" /mnt/ventoy

echo "4. Pre-seeding configuration and assets..."
mkdir -p /mnt/ventoy/ventoy

# Seed custom configuration
cat << 'EOF' > /mnt/ventoy/ventoy/ventoy.json
{
  "control": [
    { "VTOY_DEFAULT_SEARCH_ROOT": "/ISO" },
    { "VTOY_MENU_TIMEOUT": 10 }
  ]
}
EOF

# Copy local seed directories if mounted
if [ -d "/seed" ]; then
    cp -r /seed/* /mnt/ventoy/
fi

echo "5. Cleaning up mounts..."
sync
umount /mnt/ventoy
losetup -d "${LOOP_DEV}"

echo "Build complete: ${IMAGE_NAME}"

Step 3: Build and Execute the Container

Place your pre-seeded files (such as automated kickstart scripts, unattend XML files, themes, and ISOs) into a local directory named seed. Then, run the following commands:

  1. Build the Docker image:

    docker build -t ventoy-builder .

  2. Generate the seeded image by mounting an output folder and your seed files:

    docker run --privileged --rm \
  -v $(pwd)/output:/output \
  -v $(pwd)/seed:/seed \
  -e IMAGE_SIZE_MB=8192 \
  ventoy-builder

Deploying the Custom Image

The generated ventoy_custom.img in the output directory contains both the standard Ventoy boot partitions (supporting UEFI and legacy BIOS) and the pre-populated data partition. You can flash this output file directly to any physical drive using standard flashing tools:

dd if=output/ventoy_custom.img of=/dev/sdX bs=4M status=progress conv=fsync

Replace /dev/sdX with the destination drive. Once written, the drive will boot directly into the Ventoy environment using your custom configurations and pre-loaded assets.
