Ventoy 32-Bit UEFI Fallbacks with BOOTIA32.EFI

Ventoy resolves architecture compatibility issues on devices with 32-bit UEFI firmware by deploying a multi-architecture boot partition containing BOOTIA32.EFI. While modern PCs predominantly use 64-bit UEFI (BOOTX64.EFI), many legacy devices—such as older Intel Atom tablets and budget convertibles—feature 64-bit processors paired with strictly 32-bit UEFI firmware. Ventoy natively integrates the standardized BOOTIA32.EFI executable into its boot structure, allowing the firmware to automatically detect, initialize, and route boot execution to its core environment before mounting and launching target ISO files.

When a device boots in UEFI mode, the firmware looks for the default fallback bootloader path: \EFI\BOOT\ on the active EFI System Partition (ESP). In a standard Ventoy installation, the drive is divided into an accessible storage partition for image files and a hidden, dedicated FAT-formatted partition named VTOYEFI. Ventoy populates VTOYEFI with bootloaders compiled for various platforms, placing both 64-bit (BOOTX64.EFI) and 32-bit (BOOTIA32.EFI) executables alongside ARM and legacy MBR loaders in the same fallback directory.

If the host machine has 32-bit UEFI firmware, it ignores the 64-bit binaries and automatically executes \EFI\BOOT\BOOTIA32.EFI. This file is a customized 32-bit build of GNU GRUB2. Once executed, it initializes hardware services using 32-bit EFI runtime and boot services, configures display protocols, and maps Ventoy's internal runtime modules into memory. It then renders the Ventoy graphical selection menu.

After a user selects an operating system image, Ventoy uses its virtual disk framework to expose the ISO contents directly in memory. However, booting an operating system from a 32-bit UEFI loader introduces constraints based on the target OS:

  • Native 32-Bit Operating Systems: If the selected ISO contains a 32-bit UEFI bootloader and kernel (such as a 32-bit Linux distribution or 32-bit Windows installer), BOOTIA32.EFI chains directly into the target image's \EFI\BOOT\BOOTIA32.EFI without architectural mismatch.
  • 64-Bit Operating Systems (Mixed-Mode Booting): For 64-bit OS images running on 64-bit CPUs with 32-bit firmware, BOOTIA32.EFI leverages the Linux EFI Handover Protocol (CONFIG_EFI_MIXED). The 32-bit GRUB environment sets up the kernel parameters, extracts the 64-bit kernel and initramfs, and hands execution over to the 64-bit kernel entry point while maintaining the necessary 32-bit firmware interface wrappers.

Through this dual-loader setup and adherence to the UEFI fallback specification, Ventoy ensures seamless boot capability across standard 64-bit systems and mixed-mode 32-bit firmware without requiring user intervention or manual configuration.
