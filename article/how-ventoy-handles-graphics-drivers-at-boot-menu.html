How Ventoy Handles Graphics Drivers at Boot Menu

Ventoy does not load or use hardware-specific operating system graphics drivers to display its boot menu. Because the menu runs in a pre-boot environment before any operating system kernel is loaded, Ventoy relies entirely on standard firmware-level display interfaces provided by the system's motherboard and GPU firmware. Depending on whether the system boots via modern UEFI or legacy BIOS, Ventoy leverages either the UEFI Graphics Output Protocol (GOP) or VESA BIOS Extensions (VBE) to render its graphical interface.

The Pre-Boot Environment and GRUB

Ventoy is built on a customized implementation of GNU GRUB2. At this early stage of the boot sequence, full operating system drivers—such as proprietary NVIDIA packages or complex open-source AMD and Intel drivers—cannot function. Instead, GRUB operates within the constraints of the system's active firmware, executing code directly on the bare metal.

Display Handling in UEFI Mode

On modern systems booted using UEFI, Ventoy relies on the Graphics Output Protocol (GOP):

  • Firmware Option ROMs: The graphics card provides an Option ROM (or integrated firmware for CPUs with integrated graphics) conforming to the UEFI specification. This firmware exposes standard GOP services to the pre-boot environment.
  • Framebuffer Control: GOP provides a hardware-agnostic, linear framebuffer. Ventoy writes directly to this framebuffer to render the background, fonts, and selection boxes.
  • Resolution Negotiation: Ventoy queries GOP for the native or supported display modes exposed by the video card's firmware. If a high-resolution display mode (such as 1920x1080) is supported by the firmware, Ventoy sets the display mode accordingly without needing specific GPU architectures or registers.

Display Handling in Legacy BIOS Mode

When booting on older hardware or in CSM (Compatibility Support Module) mode, Ventoy relies on legacy standards:

  • VESA BIOS Extensions (VBE): Ventoy uses VBE via standard BIOS interrupts (such as INT 10h) to query supported display modes and configure a linear framebuffer.
  • Resolution Limits: Legacy BIOS display resolution is constrained by what the video card's legacy VBIOS supports. If high resolutions are unavailable, Ventoy defaults to common standard resolutions like 1024x768 or 800x600.
  • VGA Fallback: If VBE fails or is unsupported, the system falls back to standard VGA text mode or 16-color VGA graphics.

Theme Rendering and Fallback Mechanisms

Ventoy uses GRUB's built-in graphical engine (gfxterm and gfxmenu) to draw its visual interface over the framebuffer established by GOP or VBE:

  1. Resolution Detection: Ventoy attempts to match the screen resolution to the configured theme or the highest safe mode reported by the firmware.
  2. Text Mode Fallback: If a display adapter or monitor fails to negotiate a graphical mode via GOP or VESA, Ventoy automatically falls back to standard text mode, ensuring that boot functionality is preserved even when graphical rendering fails.
  3. Driver Handoff: Once a user selects an ISO or image to boot, Ventoy's pre-boot environment terminates. The selected operating system's kernel is then loaded into memory, taking over display hardware initialization and loading its own hardware-specific graphics drivers.
