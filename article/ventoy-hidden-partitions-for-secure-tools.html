Ventoy Hidden Partitions for Secure Tools

Ventoy provides flexible disk management features that allow technicians to isolate and secure proprietary diagnostic tools using reserved space, custom partitions, and built-in access controls. While Ventoy's core bootloader must be able to read ISO files to execute them, administrators can combine Ventoy’s partition preservation settings with access-restriction plugins and encrypted secondary storage to safeguard sensitive corporate utilities against unauthorized copying or tampering.

Default Structure vs. Custom Partitioning

By default, Ventoy formats a flash drive into two partitions: a large partition (usually exFAT) where bootable images reside, and a small, hidden FAT partition containing the core EFI and legacy boot code. Standard ISO, WIM, and VHD files placed in the main partition are visible to any computer the drive is plugged into.

To secure proprietary tools, Ventoy allows users to preserve space at the end of the disk during the initial installation. By enabling the "Preserve space in the bottom of the disk" option in the Ventoy GUI or using the -r argument in the CLI, you can leave an unallocated region on the USB drive. This unallocated space can subsequently be formatted into a third, separate partition.

Techniques for Securing Diagnostic Files

Securing proprietary tools on a Ventoy drive generally requires a hybrid approach depending on whether the security threat is unauthorized booting or unauthorized file copying.

1. Password-Protecting Bootable Images

Ventoy does not natively boot from fully encrypted partitions (such as full-disk BitLocker or LUKS) because the bootloader needs read access to the image to map it into memory. Instead, native boot-level security is achieved using the Ventoy Password Plugin. By defining credentials inside the ventoy.json configuration file, administrators can:

  • Lock the entire boot menu behind a global password.
  • Assign individual passwords to specific proprietary diagnostic ISOs.
  • Hash the passwords using SHA-256 to prevent plaintext credential theft from the configuration file.

2. Hidden or Non-Standard Partitions

You can configure the reserved partition with a filesystem unrecognized by standard consumer operating systems (such as ext4 or Btrfs when plugged into Windows), or strip its drive letter and mark it as hidden using disk partitioning utilities like diskpart (using the gpt attributes=0x8000000000000001 or MBR hidden partition IDs). This prevents everyday users from browsing, extracting, or duplicating the files when the USB drive is plugged into an active operating system.

3. Two-Stage Boot with Encrypted Storage

For high-security environments, the most effective method is a two-stage deployment:

  1. Place a generic, non-proprietary WinPE or Linux Live image on the public Ventoy partition.
  2. Store the proprietary diagnostic software on the third, reserved partition encrypted with BitLocker, LUKS, or VeraCrypt.
  3. Boot into the generic WinPE/Linux environment via Ventoy, then authenticate to unlock the encrypted partition in memory, running the proprietary tools from the protected volume.

This architecture ensures that even if the Ventoy drive is lost, the proprietary diagnostic suite cannot be extracted directly from the USB drive without the decryption key.
