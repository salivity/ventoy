How to Mount Data Archives in Ventoy Rescue Tools

Ventoy is widely recognized for its ability to boot multiple operating systems from a single USB drive, but it can also serve as a direct storage source during system recovery. When you boot into an administrative rescue tool—such as WinPE, SystemRescue, or Hiren’s BootCD—the underlying Ventoy drive remains visible to the operating system. This allows administrative environments to mount the storage partition directly, providing immediate access to plain data archives, portable utilities, drivers, and disk images without needing secondary storage media.

Understanding the Ventoy Drive Structure

When Ventoy formats a flash drive, it divides the storage into two distinct partitions:

  1. Partition 1 (Data Partition): This is the primary, large partition formatted in exFAT by default (though it can be reformatted to NTFS, ext4, or FAT32). It holds your bootable ISOs, WIMs, and ordinary storage files.
  2. Partition 2 (VTOYEFI): A hidden, low-capacity FAT partition reserved exclusively for UEFI/BIOS bootloaders and Ventoy core files.

Because Partition 1 functions as a standard file storage partition, any administrative tool that boots into RAM can still communicate with the USB controller and read data stored alongside your ISOs.

Accessing Archives in Linux-Based Rescue Tools

Linux-based recovery tools, such as SystemRescue, GParted Live, or standard distribution live environments, treat the Ventoy USB drive as a standard block device.

  1. Identify the Partition: Open a terminal and run lsblk or fdisk -l to find the USB drive identifier (typically /dev/sdb1 or /dev/sdc1).
  2. Mount the Data Partition: Create a mount point and attach the partition: 
    mkdir -p /mnt/ventoy
mount /dev/sdb1 /mnt/ventoy
  3. Read Plain Archives: Navigate to your mounted directory. From here, you can extract or read standard archives directly using built-in command-line tools:
    • Tarballs: tar -xvf /mnt/ventoy/backup.tar.gz -C /target
    • ZIP Files: unzip /mnt/ventoy/tools.zip -d /target
    • Raw ISO/IMG Archives: Mount them via loop device using mount -o loop /mnt/ventoy/data.iso /mnt/iso

Accessing Archives in Windows-Based Rescue Tools (WinPE)

Windows Preinstallation Environments (WinPE), including custom suites like Hiren's BootCD PE or Sergei Strelec, handle the Ventoy data partition natively.

  1. Automatic Assignment: Upon booting, the Windows environment initializes USB storage drivers and automatically assigns a drive letter (such as D: or E:) to Partition 1 of the Ventoy stick.
  2. Archive Handling: Using the built-in Windows Explorer or bundled utilities like 7-Zip, navigate to the assigned drive letter. You can open, extract, or edit .zip, .7z, .cab, and .tar files as you would on a standard desktop system.
  3. Mounting Disk Images: WinPE allows native mounting of .iso and .vhd data containers directly through Disk Management or the right-click context menu.

Important Considerations

  • Filesystem Support: Ensure the rescue tool supports the filesystem used on Ventoy's data partition. While exFAT works across most modern rescue discs, specialized or older minimalist Linux tools may require NTFS or ext4.
  • Read/Write Operations: By default, files on Partition 1 can be modified from within the rescue tool. If you are extracting archives to write to a damaged target disk, ensure you do not accidentally overwrite your Ventoy storage files.
  • Avoid Modifying Active ISOs: Do not attempt to alter or unpack the specific ISO file that the rescue environment is currently running from, as this can crash the active environment. Plain data archives stored alongside the ISOs, however, can be read safely.
