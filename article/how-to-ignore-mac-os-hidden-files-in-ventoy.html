How to Ignore macOS Hidden Files in Ventoy

Ventoy does not have a dedicated toggle to automatically filter out macOS metadata files (such as ._* AppleDouble files), but you can prevent them from appearing on your boot menu. When macOS writes to non-APFS drives, it creates hidden companion files prefixed with ._ for every file copied, and Ventoy often indexes them as bootable ISOs. You can eliminate these files from your boot screen by using Ventoy’s image_list plugin, restricting search directories, or removing the metadata directly using native macOS terminal commands.

Why Ventoy Shows ._* Files

When you connect a Ventoy USB drive to a Mac and copy over an ISO file (such as ubuntu.iso), macOS automatically creates a hidden metadata file named ._ubuntu.iso. Because this file retains the .iso extension, Ventoy’s scanning engine detects it as a bootable disk image. Selecting it on the boot screen leads to boot errors because it contains only file metadata rather than an actual operating system.

Method 1: Whitelist Files with the Image List Plugin

The most reliable way to force Ventoy to ignore unwanted files is to define an explicit list of bootable images using the image_list plugin in the ventoy.json configuration file.

  1. Navigate to the ventoy directory on your USB drive's data partition (create the folder named ventoy in lowercase if it does not exist).
  2. Create or edit a file named ventoy.json.
  3. Add the image_list array to specify only the exact ISO files you want to appear in the menu:
{
    "image_list": [
        "/ISO/ubuntu-22.04-desktop-amd64.iso",
        "/ISO/Win11_English_x64.iso"
    ]
}

By explicitly declaring which images to display, Ventoy will ignore all other files in the directory, including any ._* files generated by macOS.

Method 2: Restrict the Search Directory

By default, Ventoy recursively scans the entire partition. You can isolate your images to a single, clean directory to minimize the risk of scanning clutter.

Add the VTOY_DEFAULT_SEARCH_ROOT parameter to your ventoy.json file inside the control block:

{
    "control": [
        { "VTOY_DEFAULT_SEARCH_ROOT": "/ISO" }
    ]
}

Place all valid images inside an /ISO folder. While macOS might still create ._ files inside that folder, limiting the scan scope ensures system files from the drive root and other subfolders are ignored.

Method 3: Clean Hidden Files from macOS Before Ejecting

If you do not want to maintain a manual whitelist in ventoy.json, you can remove the AppleDouble files directly from macOS before ejecting the drive.

  1. Open the Terminal app on your Mac.
  2. Run the dot_clean utility followed by the path to your Ventoy USB drive:
dot_clean /Volumes/Ventoy

(Replace /Volumes/Ventoy with the actual mount name of your USB drive.)

This command merges or deletes all ._* companion files on the drive. Once finished, safely eject the USB drive immediately so macOS does not generate new metadata files upon disconnection.
