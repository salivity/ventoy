How MSPs Customize Ventoy for IT Technicians

Managed service providers (MSPs) frequently deploy Ventoy on technician USB drives to streamline hardware diagnostics, operating system deployments, and disaster recovery tasks. Customizing the Ventoy interface allows MSPs to establish a consistent workflow, apply internal branding, restrict unauthorized access, and automate system provisioning. This guide details how MSPs configure Ventoy’s directory structure, theme files, and central ventoy.json file to create an efficient, specialized bootable environment for internal technical staff.

The Foundation: The ventoy.json Configuration File

All native customizations in Ventoy stem from a single configuration file named ventoy.json. MSPs place this file inside a folder named ventoy located in the root partition of the USB drive.

A standard structure appears as follows:

USB_ROOT/
├── ventoy/
│   ├── ventoy.json
│   ├── theme/
│   │   └── msp-theme/
│   └── script/
└── ISO/
    ├── Diagnostics/
    ├── Windows/
    └── Recovery/

This JSON file controls visual themes, menu aliases, auto-install scripts, and security controls across all devices using the drive.

Applying Corporate Branding and Custom Themes

To maintain a uniform look and feel across field support tools, MSPs implement custom GRUB themes:

  1. Theme Selection: MSPs create or download a standard GRUB2 theme containing internal branding, high-contrast text for low-resolution displays, and corporate color palettes.
  2. Directory Placement: The theme assets (including theme.txt, background images, and fonts) are placed in the /ventoy/theme/ directory.
  3. Configuration: The theme is enabled via the theme key in ventoy.json: 
    {
    "theme": {
        "file": "/ventoy/theme/msp-theme/theme.txt",
        "gfxmode": "1920x1080"
    }
}

Using standard resolutions like 1920x1080 with automatic fallback ensures the interface displays correctly across modern laptops, legacy servers, and headless diagnostic monitors.

Menu Organization and Friendly Aliases

Raw ISO file names are often cryptic and prone to version mismatches. MSPs make these boot options intuitive for tier-1 and tier-2 technicians by renaming display items and assigning relevant icons.

  • Menu Aliasing: The menu_alias plugin translates raw filenames into recognizable descriptions without requiring technicians to rename the underlying ISOs: 
    {
    "menu_alias": [
        {
            "image": "/ISO/Windows/Win11_23H2_English_x64v2.iso",
            "alias": "Standard Windows 11 Field Deployment"
        },
        {
            "image": "/ISO/Diagnostics/memtest86-usb.img",
            "alias": "Hardware Diagnostics: MemTest86+"
        }
    ]
}
  • Menu Classes and Icons: MSPs map specific icons (such as Windows, Linux, or generic wrench icons) to menu options via the menu_class plugin to speed up navigation.

Automating Installs with Injection and Answer Files

To reduce deployment time on client hardware, MSPs link answer files directly to ISOs through Ventoy's auto_install plugin:

{
    "auto_install": [
        {
            "image": "/ISO/Windows/Win11_23H2_English_x64v2.iso",
            "template": "/ventoy/script/unattend_client_setup.xml"
        }
    ]
}

This setup enables technicians to boot a clean operating system image while automatically applying local administrator accounts, standard partition schemes, and initial network configurations.

Restricting Access and Securing Diagnostic Tools

Field drives are vulnerable to loss or theft, creating a potential security risk if proprietary rescue environments or pre-configured admin images are exposed. MSPs secure these boot environments using Ventoy’s built-in access controls:

  • Global Passwords: Setting a global password prevents the drive from showing any boot items until unlocked by a technician.
  • Image-Specific Passwords: Locking specific directories or administrative ISOs while leaving general hardware diagnostic tools accessible without authentication.
  • Password Hashing: Ventoy supports SHA-256 and SHA-512 password hashes inside ventoy.json to prevent cleartext exposure of internal credentials: 
    {
    "control": [
        { "image": "/ISO/Recovery/AdminTools.iso", "pwdhash": "your_sha256_hash_here" }
    ]
}

Standardizing Rollouts Across the Team

Rather than configuring drives manually, MSPs maintain their custom Ventoy configurations in a centralized Git repository. When a technician receives a new drive, a deployment script runs Ventoy’s command-line installer, clones the repository containing the ventoy folder structure, and pulls the latest approved ISO images from an internal network share. This ensures every technician carries an identical, up-to-date toolkit.
