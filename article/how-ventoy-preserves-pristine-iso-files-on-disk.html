How Ventoy Preserves Pristine ISO Files on Disk

Ventoy is an open-source tool that allows users to create bootable USB drives simply by copying disk images onto the media. Unlike traditional utilities that extract files or overwrite the drive's partition structure, Ventoy leaves the original ISO files completely unmodified and readable as standard files on a typical filesystem. This article explains the technical mechanics behind Ventoy's non-destructive approach, detailing how virtual disk emulation, memory hooking, and separated persistence mechanisms preserve the byte-for-byte integrity of your original images.

Traditional Flashing vs. The Ventoy Approach

Standard image writers, such as Rufus or the Unix dd utility, extract the filesystem contained inside an ISO or write its raw disk blocks directly over the physical storage device. This process erases existing data, alters the drive layout, and prevents the image from functioning as a standalone file.

Ventoy takes the opposite approach. When initialized, it formats the drive into two distinct partitions: a small, hidden FAT partition containing the Ventoy bootloader (GRUB-based) and core drivers, and a primary partition formatted as exFAT, NTFS, or ext4. The primary partition acts as standard storage where users drag and drop ISO, WIM, IMG, or VHD files. Because these files reside as regular objects in a filesystem, they are never uncompressed, patched, or written over at the block level.

In-Memory Hooking and BIOS/UEFI Emulation

The core mechanism enabling Ventoy to preserve ISO integrity is runtime virtualization. When a system boots via Ventoy, the following process occurs:

  1. Boot Menu Selection: Ventoy scans the storage partition, detects valid image files, and displays a menu.
  2. Chainloading and Emulation: Once an ISO is selected, Ventoy does not modify the image on the disk. Instead, it hooks into system firmware interfaces—the BIOS INT 13h interrupt or the UEFI EFI_BLOCK_IO_PROTOCOL.
  3. Virtual CD-ROM Creation: Through these hooks, Ventoy presents the chosen ISO file to the computer's firmware as if it were a physical optical drive (CD/DVD-ROM) or a secondary drive device.
  4. Boot Execution: The system firmware reads the boot sector directly from the mapped file blocks in memory, launching the operating system installer or live environment without altering a single byte on the physical disk.

OS-Level Loopback Integration

Modern operating systems usually switch to protected mode (or long mode) and load their own hardware drivers, which bypasses the firmware-level BIOS/UEFI hooks. Ordinarily, this causes the OS to lose track of the virtualized ISO drive and fail during the boot process.

To overcome this without touching the original ISO, Ventoy injects minimal runtime hooks into the OS boot process (such as the Linux initramfs or the Windows WinPE environment). It instructs the loading kernel to mount the ISO file from the storage partition as a loopback device. Because the loop device mounts the file in read-only mode, the operating system interacts with the contents of the image while the underlying file remains unchanged.

Isolated Persistence and Configuration

When users require changes to persist across reboots (such as in live Linux environments), Ventoy avoids writing data back to the image file. Instead, it supports persistence plugins that redirect write operations to an external image file (typically a .dat file). The base ISO remains completely read-only, ensuring that its SHA-256 and MD5 checksums remain identical to the distribution provided by the original developer.
