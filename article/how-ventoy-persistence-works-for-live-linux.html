How Ventoy Persistence Works for Live Linux

The Ventoy persistence plugin allows users to run live Linux distributions from a USB drive while retaining system settings, installed software, and personal files across reboots. Standard live Linux media typically operates entirely in temporary system memory (RAM), discarding all changes when powered down. Ventoy solves this limitation by pairing unmodified ISO files with dedicated virtual disk images and injecting native persistence boot parameters during the bootloader stage, seamlessly bridging the gap between a portable live environment and a fully installed operating system.

The Problem with Traditional Live Systems

When a standard live Linux distribution boots from an ISO, the bootloader mounts a compressed, read-only filesystem (typically a SquashFS image). Any changes made during the session—such as creating documents, configuring Wi-Fi, or installing software—are written to a temporary RAM-based filesystem (such as tmpfs). Because RAM is volatile, shutting down or restarting the machine clears these memory buffers, returning the system to its original state upon the next boot.

How Ventoy Achieves Persistence

Ventoy implements persistence without extracting or modifying the underlying distribution ISOs. It accomplishes this through three core components: a virtual storage container, configuration mapping, and boot parameter injection.

1. The Persistence Image File

Instead of creating dedicated disk partitions on the USB drive, Ventoy relies on pre-allocated image files (typically with a .dat or .img extension). These files are virtual hard disks formatted with a standard Linux filesystem, such as ext4.

Within this virtual disk, the operating system stores directory structures and files that differ from the read-only base image. Because the container is simply a file on the USB's standard exFAT or NTFS storage partition, users can easily back it up, resize it, or replace it from any host OS.

2. Configuration via ventoy.json

Ventoy uses a structured configuration file named ventoy.json, located in the ventoy directory on the drive. This file defines which ISO image pairs with which persistence file. A standard mapping entry links the target ISO path to the corresponding .dat file path.

This approach allows different Linux distributions on the same USB drive to maintain their own separate, isolated persistent environments, or even allow a single ISO to alternate between multiple distinct persistence states.

3. Kernel Parameter Hooking and OverlayFS

Different Linux distributions implement persistence through different live-boot scripts (such as Debian's live-boot, Ubuntu's casper, or Fedora's dracut). When a user selects an ISO with an assigned persistence image:

  1. Parameter Detection: Ventoy identifies the distribution and automatically appends the correct boot parameters to the Linux kernel command line (for example, adding persistence for Debian or persistent for Ubuntu).
  2. Device Loop Mounting: During early boot (initramfs), the live system looks for persistence media. Ventoy's background hooks expose the .dat file as a virtual loopback block device labeled appropriately (such as casper-rw or persistence).
  3. Union Mounting: The kernel uses an overlay filesystem (such as OverlayFS). It mounts the read-only SquashFS from the ISO as the base layer (lowerdir) and the mounted persistence image as the writable layer (upperdir).

When an application reads a file, the system checks the writable layer first; if the file has not been modified, it reads the original version from the base ISO. When any file is written, modified, or deleted, the changes are committed exclusively to the writable persistence image.

Advantages of the Plugin Approach

  • Isolation: The original ISO files remain bit-for-bit identical to the official releases, preventing corruption.
  • Portability and Backup: Entire persistent environments can be backed up or restored simply by copying a single .dat file.
  • Multi-Boot Compatibility: Multiple persistent Linux installations can coexist on a single drive alongside normal, non-persistent ISOs and standard storage files.
